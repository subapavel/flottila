# F-111 — an indexed read of a document array costs O(i), so an index loop is quadratic

- **Assumption**: ADR-0034 Decision: "Tape walks charge `tick(entries stepped)` once per walk:
  `.[n]`, a length on a view…". The tape entry holds only the container's end (ADR-0002); no cached
  index or skip table exists in ADR-0002, 0003, 0004, 0008 or 0034. `ArrayView.get(RunState,int)`
  implements that as written.
- **How it fails**: a loop that indexes a document array, `. as $a | reduce range(0;length) as $i
  (0; . + $a[$i])`, pays i entries per read, n²/2 in all. At 1e5 elements it takes 19.0 s on the
  CLI against 0.30 s with `[.[]] as $a` and 65 ms on jq-ref; under `Limits.embedded()` it ends on
  the step budget from about 45 000 elements (n²/2 ≥ 10⁹, by arithmetic). No gate scenario G1–G7
  has an indexed read, which is why it went unseen until #119's recursion cells (all five shapes
  ended on BUDGET STEPS at 1e6).
- **Severity**: major. No value is wrong, but a common jq idiom becomes unusable at sizes jq handles
  in milliseconds.
- **Evidence**: grilling-adviser, 2026-11-16 (#119), re-run on impl/119's `jq-cli/target/jqj`;
  `.logs/119-shots{,-1e5,-1e4}.log` and `119-jq-ref-cells.log` in the impl/119 worktree.
- **Change made**: owner, 2026-11-16 (Fable's recommendation A): the fix is a class C ticket of
  spec 6 (Speed), where ADR-0023 puts the step default and the fast paths; ADR-0034 carries a
  pointer. #119's recursion cells copy the array first (`[.[]] as $a`) so they measure recursion.
  Open for spec 6's grilling: the mechanism (a per-run memo of the last array position, or a lazy
  offset table that is charged and re-pins `NavigationBudgetTest`); whether `length` on a view and
  negative indexes get the same fix; whether natives that probe a document array (`bsearch`,
  `nth`, `first`, `last`) pay the walk per probe; and whether spec 6 sets the step default before
  or after the fix.

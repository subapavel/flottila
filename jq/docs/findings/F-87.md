# F-87 — jqj's command line lets a termination escape

- **Assumption** (ADR-0017 "Exit codes"): "a run ended by any other termination ends 5"; DEVIATIONS
  "Array length limit" promises "exit 5 and Bytes-built budget exceeded" on the command line.
- **How it fails**: `jq-cli`'s `Main.run(Invocation)` catches no `JqTermination`. Spec 2a's CLI limits
  never ended a run, so nothing showed it. #107's recursion-depth and STACK terminations now reach
  `Main` uncaught, and `DiffRunner`, which runs jqj in-process, scores them CRASH.
- **Severity**: major (blocks #107; a budget end on the command line is a crash, not rc 5).
- **Evidence**: #107 designer draft (conflict C3); the grilling-adviser's ruling of 2026-11-14.
  jq-ref 1.8.2 on `def f: if . == 0 then 0 else (. - 1 | f) + 1 end; N | f`: N up to 10^7 prints N,
  rc 0; 2·10^7 and 10^8 print `jq: error: cannot allocate memory`, rc 134.
- **Change made** (proposed by the grilling-adviser for the owner under the delegation of 2026-11-14):
  - Ticket #197 (class B, before #107). For every cause but HALT, `Main.run(Invocation)` flushes the
    results so far, writes `jq: error: <message>` to stderr and returns 5. `run(Invocation,
    UnaryOperator)` keeps throwing (`CompileModes.cli`, ADR-0020).
  - No `(at <file>:N)`: the line stays distinct from a catchable `error(...)`.
  - #107 amends DEVIATIONS "Recursion depth on the command line" with jqj's line, rc 5 and jq-ref's
    two ends above. No STACK row until the calibration (S2b.6) shows whether the backstop is reachable.

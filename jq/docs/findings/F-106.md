# F-106 — ADR-0040 forbade pinning a lifted count that the depth rule fixes

- **Assumption**: ADR-0040 "The choice is greedy and top-down": "Tests pin results and the node
  bound, not the number of lifted functions."
- **How it fails**: #114's approved red `InlineDepthTest.anExpansionNested512DeepRuns` asserts that a
  512-deep call chain lifts exactly one function. Approved tests already pin lifted lists where the
  rule leaves one answer (`InlineCostKindsTest`, `OperatorChainTest`, `IrDepthTest`, `InlineCapTest`).
- **Evidence** (grilling-adviser, 2026-11-15, read of impl/114 at 9bccefb): `Resolver.fit` lifts only
  at nesting depth 511, which is `f1`. Every call in the chain measures one node and one level, so the
  node and level tests never fire, and `f1`'s body holds no call. A chain of n lifts floor(n/512)
  functions. The count is 1 under each lifting order the ADR names, so the assertion does not bind
  spec 6's as-late-as-possible choice.
- **Severity**: minor. The ADR's wording was wider than its reason, which is the measure's upper bounds.
- **Change made**: the ADR-0040 sentence is narrowed to the measure's choices, and the depth lift may be
  pinned. The test stays `hasSize(1)`, not `containsExactly("f1/0")`. Loosening it to `isNotEmpty()`
  was refused, because it would accept a Resolver that lifts all 512 definitions.
- **Second Standards FAIL on #114** (907e52a): new edge rows pinned `p4/0` and `f/0` in filters
  where another lifting order lifts another function (a `..` row reaches the prelude's `recurse`).
  The designer's rewrite of #114 reads "a filter of one definition" as one non-recursive definition
  reached, prelude definitions counted; elsewhere a test pins only how many functions an edge adds.
  The ADR sentence now says so.

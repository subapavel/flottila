# F-91 — a forked test JVM can die without failing the Maven build

- **Assumption** (ADR-0014; the gates' step 1): when `mvn verify` exits 0, every test of every module
  ran.
- **How it fails**:
  - #112's implementer ran the gate with `-Xmx384m` in `JAVA_TOOL_OPTIONS`.
  - `HugeConstantKeyTest` ran out of heap, and the jq-core Surefire fork died with no report.
  - Maven still reported success, with 3 025 of jq-core's 8 820 tests run.
  - Only the coverage ratchet caught it (jq-core at 98 % and 96 %).
  - Under `ulimit -v 2000000` the gate is ENVIRONMENT_BLOCKED for another reason: `FreshJvm` strips
    `JAVA_TOOL_OPTIONS`, so its children try to reserve 1 GiB of class space and cannot start.
- **Severity**: major as reported (a green step 1 hiding unrun tests); not reproduced, see below.
- **Evidence**: #112 implementer hand-back, 2026-11-15
  (`.logs/112-gate.log` in its worktree, NOT_RUN by the architect).
- **Re-measured** (2026-11-17, on `main` with Surefire 3.6.1): the green exit was not reproduced.
  - The same run, `JAVA_TOOL_OPTIONS=-Xmx384m ../mvnw -B -Djacoco.skip=true -pl jq-core -am verify`,
    runs out of heap in `HugeConstantKeyTest` after 3 268 tests. Surefire reports "There was an
    error in the forked process: java.lang.OutOfMemoryError: Java heap space" and Maven exits 1.
  - A test JVM that calls `System.exit(0)` or `Runtime.halt(0)`, or runs out of heap on the test
    thread, in a static initializer, in its output or in an assertion message, fails the build
    too, even with `-Dmaven.test.failure.ignore=true`.
  - In every module of the platform, the jq engine and the mapping that runs a test, the build of
    the module fails when its test JVM ends with exit code 0 and no goodbye once its first test has
    finished (`ci/fork_kill_check.py`).
  - The 2026-11-15 claim rested on a log that nobody checked.
- **Known gap** (in how tests are written, not in the runner): an OutOfMemoryError on a thread
  that a test starts, when nothing reports it, leaves the build green. The JVM lives on and every
  test still runs.
- **Change made**:
  - `ci/fork_kill_check.py` runs nightly in the platform's `ci.yml` for every reactor. It ends
    every test JVM once its first test finishes and fails when a module that ran a test still
    passes.
  - The agent rule stays: never run Maven under `ulimit -v` or with `-Xmx` in
    `JAVA_TOOL_OPTIONS`. The deep-recursion and calibration tests start child JVMs that need their
    own stack and heap.

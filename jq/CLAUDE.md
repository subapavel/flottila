# Rail8 jq — the engine's technical rules

The way of working is the repository's: `AGENTS.md` at the root. The rules below are the jq
engine's own and hold inside `jq/`.

The jq language on Java 25: a filter is compiled once (to an IR, then to an interpreter tree) and
runs directly over JSON bytes, without building an object tree of the input. Speed and bounded
memory come first. Rail8 uses it through a jq step; nothing here depends on Rail8's platform code.

## Read before work

- `docs/FOUNDING-ARCHITECTURE.md`: the agreed direction.
- `GLOSSARY.md`: the project's language. Use its terms in code and tests.
- `docs/adr/`: the decisions that bind the area you touch. Contradicting one needs the owner-proxy.
  Where an ADR prescribes a way of working (roles, ticket classes, integration branches, gates),
  `AGENTS.md` overrides it.
- `docs/CODING_STANDARDS.md`: the coding standard.
- `DEVIATIONS.md`: where the engine differs from jq on purpose, with the reason.

## Checks

- Every change: `../mvnw -B -Djacoco.skip=true verify` in `jq/` (`.github/workflows/jq-ci.yml`):
  the build with its unit and oracle tests, licences, bans and the query-core word check.
- Nightly, as a report that blocks nothing (`jq-nightly.yml`): mutation tests, the calibration
  matrix, the recordings and the compile-mode oracle against the reference jq, the benchmarks
  with the ratchet, the script tests and the Windows build.
- Never run Maven under `ulimit -v` or with `-Xmx` in `JAVA_TOOL_OPTIONS`: the deep-recursion and
  calibration tests start child JVMs that need their own stack and heap.

## Rules

- A change starts from a failing check: a test, an oracle case or a ratchet entry.
- Never weaken, skip or delete a test, an oracle case or a ratchet entry to go green.
- Ratchet files (`ratchet/`) are regenerated by `scripts/ratchet.java`, never edited by hand.
- jq's behaviour: the reference jq 1.8.2 binary (`/usr/local/bin/jq-ref`, from jq's GitHub
  release) and jq's own test files decide what a filter does, never memory. A difference kept on
  purpose goes into `DEVIATIONS.md` with its reason. Expected outputs of recorded cases (`*.rec`)
  are written by `scripts/oracle-record.sh` only.
- `query-core` never mentions JSON or jq: `scripts/check-core-neutral.sh`, run by the build. The
  project's names (`dev.rail8.jq`, `rail8-jq-*`) are names, not the word.
- Recursion is bounded by `Limits.recursionDepth()`: the library's default, `Limits.embedded()`,
  is 10 000 live activations; the command line, `Limits.cli()`, keeps 4 194 304 as jq does. Deep
  recursion past the Java stack runs on the heap-form trampoline; keep both paths.
- Dependencies: Apache 2.0, MIT, MIT-0, BSD, EDL 1.0, ISC, 0BSD, MPL 2.0, EPL only; a dual licence
  counts under its allowed alternative. The list covers every compile, runtime and test
  dependency. Exceptions: JMH in `bench/jmh` only; source under the SunPro (fdlibm) notice,
  translated for 11 math builtins only (ADR-0055). Maven plugins are tools (any OSI licence). A
  new dependency or exception is a question for the owner-proxy.
- Files copied or translated from jq (its function library written in jq, its test files, the
  `jv_parse.c` port) keep jq's copyright notice and are listed in `NOTICE`. The manual's prose is
  not copied; its examples, as jq's `man.test` and `manonig.test` carry them, are test resources.
- No secret, customer payload or real partner data in the repository; test inputs are synthetic.

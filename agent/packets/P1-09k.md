# P1-09k — durable step bodies (D-064, D-066; F-10)

Class C. Designer draft approved by the architect. Split into two rows, each one commit:
- **P1-09k1** run-scoped body keys (`Envelope.ATTEMPT`, `nextKey`) and the writers that use them. No recording change.
- **P1-09k2** the run trail: every kept step body persisted at run end before its row, metadata-only above the bound. F-10, §8 edit.

## P1-09k1 — run-scoped keys
- api `Envelope`: `Key<Integer> ATTEMPT` (prop). `BlobKey nextKey()` and `nextKey(String part)` → (id, step+1, part); from the
  second attempt the part is suffixed `~<attempt>`; a part containing `~` → IAE.
- FlowWorker sets ATTEMPT on the rebuilt ingress when `item.attempts() > 1`; Replay.from / retry drop it.
- Writers switch from `BlobKey.body(...)`-style construction to `nextKey`: XsltStepFactory:94, XPathExpressions:84, HttpComponent:309,
  MockComponent:189, testkit FakeRuntime:88 (locate by content).
- First-attempt keys unchanged; no BlobKey or schema change. FIX-35's ISE stays the guard for writers that build keys themselves.
- Tests: EnvelopeTest nextKeyIsTheNextStepsBodyKey, fromTheSecondAttemptNextKeyCarriesIt, aPartWithTheSeparatorIsRefused;
  FlowWorkerTest aSecondAttemptWritesItsStepBodiesUnderItsAttempt; ReplayTest aReplayDropsTheAttempt;
  ComponentContract aReplyOfASecondAttemptIsKeyedByItsAttempt (real and mock) and the same for the xslt step.
- Mutants: ATTEMPT never set; set on attempt 1; suffix dropped; Replay keeps ATTEMPT; separator check dropped.

## P1-09k2 — the run trail
- New core `record.Trail` (final), bound as a ScopedValue (as MessageContext) around `pipeline.apply` by FlowWorker.verdict,
  Delivery.sync/atMostOnce, Replay.from/retry. With a trail bound, Recorder adds (snapshot, body) to it; without one it persists then records, not awaited.
- `Trail.close()`: persist each distinct kept body key once, in the body's own store, in parallel; then hand each snapshot to the
  MessageStore keeping `bodyKey` only if that key's persist succeeded; completes when all settled; never fails. Skips keys already durable:
  the run's seed (ingress key D-058; replay input / parked key) and keys Parking persisted.
- Waiting: no step waits. Worker awaits close before `queue.complete` (crash → rerun re-records); a recording failure never changes the verdict.
  Sync answers the reply first, returns the permit after close. At-most-once lands after close. Replay returns after close.
  256 buffered snapshots → the step crossing the line waits for a flush.
- Durable ACK (202) unchanged: ingress bodies insert + ingress row + work insert. Step bodies never part of an ACK; sync reply waits for no persist.
- Above durableMax or any failed persist: row recorded metadata-only, counted, WARNING. Invariant: a row's `body_key` means a durable body.
  Replay.from refuses through its existing "recorded metadata-only" IAE. No 422 at deploy for keep + maxBodyBytes > durableMax (owner point at hand-over).
- Tests: core TrailTest (aRowReachesTheStoreOnlyAfterItsBodyPersisted; eachDistinctBodyKeyPersistsOncePerRun; theSeedAndAParkedKeyAreNotPersistedAgain;
  aFailedOrTooLargePersistRecordsTheRowMetadataOnlyAndCountsIt; aMetadataOnlySnapshotPersistsNothing; the257thSnapshotFlushesBeforeItsStepHandsOn;
  withoutATrailTheRecorderPersistsThenRecords); jqwik RecordingPropertyTest.everyKeptBodyKeyWasPersistedBeforeItsRow;
  FlowWorkerTest anItemCompletesOnlyAfterItsRunsBodiesPersisted, aRecordingFailureNeitherLeavesNorParksTheItem, aRerunOfAStampingNextKeyStepParksAtItsStepNotTheIngress;
  DeliveryTest aSyncReplyIsAnsweredBeforeItsBodiesPersistAndThePermitReturnsAfter, atMostOnceLandsAfterItsBodiesPersisted;
  ReplayTest aReplayPersistsItsStepBodiesBeforeItReturns;
  runtime StepBodiesIT (node B = new TieredBlobStore with fresh spool dir and key, new Pool, new PgMessageStore):
  aReplayFromStepThreeOnAFreshNodeAfterARestartReproducesTheStepThreeInputByteForByte (done-when; step 1 memory, step 2 spool; at-least-once and sync),
  aRerunOfAStampingStepKeepsTheFirstRowsBytesReplayableOnAFreshNode, everyKeptBodyKeyHasItsBodiesRow (anti-join = 0),
  aBodyAboveTheBoundIsRecordedMetadataOnly, aRunsLocalCopiesAreReleasedWhenItEnds.
- Wrong expectations under D-064 (fix with that reason): DeliveryTest.syncAndAtMostOnceNeverPersist ("never before the reply/ACK"),
  ParkingTest.aFailingSyncStepPersistsNothingAndParksNothing, exact persist lists in FlowWorkerTest/ParkingTest — survey first.
- Mutants: record before or alongside persist (Future.all); persist dropped; close not awaited before complete/permit; recording failure → LEAVE;
  dedupe or seed-skip dropped; fallback keeps the key; `>`→`>=` at 256.
- P1-10 must add: worker msg/s and claim→complete p99 keep vs metadata-only (passthrough, 100 KB XSLT); sync p50 with keep;
  bodies bytes/s and WAL bytes/s; bodies growth per hour.

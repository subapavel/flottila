# FIX-142 — the DLQ's recovery path must not destroy the failure it was recovering from

Class B. Depends on FIX-140 (done, 47c9b85). Read `docs/findings/F-30.md`'s addendum first — the
"Parking" paragraphs, which the architect wrote from reading the file rather than from the sweep.

## The defect, as a chain rather than as two line numbers

`Parking.wrap` (`:42-67`) catches a step's failure at `:49` and then recovers:

```java
if (handedOn[0]) throw failure;
Future<Parked> durable = park(e, step, failure);   // :55 — ALREADY INSIDE the catch at :49
Parked parked;
try {
    parked = durable.await();                      // :58
} catch (Exception parkFailure) {                  // :59 — guards ONLY the await
    if (parkFailure instanceof InterruptedException) Thread.currentThread().interrupt();
    failure.addSuppressed(parkFailure);            // :61
    throw failure;                                 // :62 — the promise: the step's failure is what leaves
}
throw new ParkedException(parked, failure);        // :64
```

Two sites are narrower than the promises above them:

- **`:86`** — `catch (RuntimeException thrown)` around `body.store().persist(body.key())`, while **two**
  javadocs promise more: `persist`'s own at `:82` ("what the store throws becomes the failed future's
  cause") and `park`'s at `:73` ("A persist that fails, **or throws**, fails the park with its cause and
  writes no row").
- **`:59`** — `catch (Exception parkFailure)`, so an `Error` from the await is not caught either.

The consequence is **FIX-140's defect one layer out**. The `park(...)` call at `:55` is inside the outer
catch but **outside** the inner try, so an `Error` from `persist` propagates straight out of the stage:
`:61` never runs, **the step's own failure is lost and replaced by the `Error`**, and there is no park,
no DLQ row and no `ParkedException`. The DLQ fails to record, fails to report that it failed, and
destroys the reason it was called.

## The shape, decided here

Not two catches patched separately. **One statement moved, so the inner try covers the park call as
well as the await**, plus the two widenings:

```java
Parked parked;
try {
    parked = park(e, step, failure).await();
} catch (Throwable parkFailure) {
    ...
}
```

`durable` is inlined and `:55` disappears into the try. `parked` stays definitely assigned at `:64`
because every path through the catch throws. Then widen `:86` to `Throwable` too, so `persist` keeps the
promise its own javadoc makes rather than relying on the caller to clean up after it.

**Keep the `InterruptedException` clause**: a cancelled run is not the step's failure (the same
distinction `:50-53` makes), and widening the catch must not change what an interrupt does.

**Add the identity guard FIX-140 established**: `if (parkFailure != failure) failure.addSuppressed(...)`,
because `addSuppressed(self)` throws `IllegalArgumentException` and that would replace the original — the
precise defect this task removes. Name FIX-140 in the comment.

Unlike in FIX-140, that guard here **has a reachable witness**, so it must have a test: a `Dlq` whose
`park` returns a failed future whose cause **is `failure` itself** makes `durable.await()` throw the very
object being recovered. `FailingDlq` already exists in
`flottila-core/src/test/java/io/flottila/core/flow/` — extend or mirror it rather than inventing another.

## Red

Every assertion below fails today. Observe and quote a real failure per case before any production line
changes.

1. an `Error` from the blob store's `persist` leaves the stage **as the step's own failure**, asserted by
   identity, with the `Error` on its suppressed list — and no DLQ row written
2. an `Error` from the `await` does the same
3. the self-suppression case: a `Dlq` failing with `failure` itself leaves `failure` unchanged and does
   **not** raise `IllegalArgumentException`. Assert on `getClass()` before `assertSame`, since a failing
   `assertSame` must format the actual value
4. the existing behaviour for a checked park failure is unchanged — the regression guard that proves the
   catch widened rather than shifted. Find the case that covers `:59` today and leave it untouched; if
   none exists, say so, because then nothing is guarding the widening

## Allowed paths

- `flottila-core/src/main/java/io/flottila/core/dlq/Parking.java`
- its test class, plus the `Dlq` fixture you extend

**`Parking.java:49` is NOT in scope.** Whether a step's own `Error` should be parked at all is a
semantic decision and belongs to **FIX-143**. Touching `:49` here would answer a question this task has
not asked.

## Note for the reviewer

The thing to be sceptical about is case 3. It is the only witness for the identity guard, exactly as in
FIX-140 where the equivalent case turned out to be the *sole* killer of that mutant — and both the
reviewer and the architect predicted wrongly there that another case would also kill it. Check that
case 3 really distinguishes the guard from its absence, and name the mutant that proves it.

# FIX-142 — node shutdown awaits bounded worker settlement (class B; review F4.3, F-29)

Architect 2026-11-09. Base: 1b8600d.
Problem (verified in code): Deployments.Flow.close (Deployments.java:358-362) calls worker.close() and discards its future;
Deployments.close (:599-612) awaits only delivery and replay within config.stopDeadline(). Node.close (Node.java:404-431) then
stops the node lease (:410) and closes journal, message store and pool (closeStores :439-460). A worker still sending an
acknowledged message cannot settle its work row afterwards; a restart repeats a send that the partner already accepted.
FlowWorker.close (FlowWorker.java:199-210) already returns a future that completes once no claim is in flight and running is empty.

## Decision
- Node shutdown (Deployments.close) awaits every running flow's worker close future together with its delivery, inside the one
  existing budget config.stopDeadline() (FLOTTILA_STOP_DEADLINE, default PT10S) counted from the start of Deployments.close. No
  new config key. Workers are stopped first (claims end), then delivery, then the wait.
- Hot-swap / undeploy keeps not awaiting the worker (D-063, FIX-30): only the node-shutdown path changes.
- Because Node.close closes the lease after deployments.close returns, node-lease and item-lease renewal continue while draining.
- Budget expiry: shutdown proceeds; one WARNING per flow names the flow and its count of unsettled items; the work rows stay as
  they are (claimed, never settled or deleted by the shutdown) and rerun after lease expiry (at-least-once, explicit in-doubt).
  A worker that finishes after its stores closed must not settle, must not throw out of Node.close, and nothing is swallowed
  silently (its failure is logged).
- D-063 gets an amendment line: node shutdown awaits worker settlement within the stop deadline (FIX-142).

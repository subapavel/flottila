# FIX-140 — recovery pins agree with sweep pins (class B; review F7.1, F-29)

Architect 2026-11-09. Base: 298ea2e.
Problem (confirmed, F-29): PgSegmentRows.PINS_BEYOND (:33-41) counts every unarchived, unlost body_refs row as a recovery pin; the
sweeper (PINNED :50-54) lets an expired kept ref (created_at ≤ keepMaxAge cutoff, no DLQ row) go and deletes its segment row and
file, while the body_refs row lives on until retention (P7D > keepMaxAge PT1H). The next start finds the ref beyond the held
extents and refuses (JournalStart:129, ACCEPT_LOSS digest) — routine expiry reads as loss.

## Decision
A kept ref pins at recovery only while its segment is still registered: the body_refs branch of PINS_BEYOND adds
`exists (select 1 from journal_segments s where s.node = $1 and s.segment = r.segment)`. A swept segment has no row (the sweep
deleted it under its own pin check, and a ref cannot be inserted against a deleted segment row — confirm the key-share/FK path and
name it in the handback). Work rows keep pinning unconditionally. A registered segment whose file vanished still refuses.

## Red tests (test-author)
SegmentSweepIT (or a JournalStart IT) .aNormallySweptKeptRefDoesNotRefuseRestart: persist, finish, advance the injected clock past
keepMaxAge, sweep (segment row and file gone, body_refs row kept), close and reopen the same journal → start succeeds, the ref reads
as expired/retired, not lost. Control .aRegisteredSegmentWhoseFileVanishedStillRefuses (row kept, file deleted → refusal with the
digest). Control .aDlqHeldRefStillPinsItsSegment (sweep leaves it; restart with the file present succeeds; with it deleted refuses).
Red log agent/work/FIX-140-red.log.

## Checks
`mvn -B -ntp -q -pl flottila-runtime -am verify -Pit`, coverage no decrease, a hand mutant dropping the new exists (killed by the
first red), restore cp+touch+cmp with the diff in the mutant log.

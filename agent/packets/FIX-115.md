# FIX-115 — a message deadline on every deployed path (class C; D-100 draft, F-24)

Architect 2026-11-03 from the designer's draft (approved, all recommended defaults: flow key `delivery.timeout` PT30S, tenant
"default", trace id = message id, a free permit still granted past the deadline). Follow-ups: FIX-116..118.

## Shape
- core scope/MessageContext: keep the record (messageId, flow, tenant, traceId, deadline); add `DEFAULT_TENANT = "default"`,
  `static MessageContext of(Envelope e, Instant deadline)`, `Envelope apply(Pipeline rest, Envelope e)` (binds, rethrows as thrown,
  same Carrier.call pattern as Trail.java:76), `remaining(Clock)` if not there; fix the deadline javadoc (nothing cancels yet).
- core FlowBuilder: one head Stage on every built pipeline (Built.pipeline(boolean) for sync/at-most-once/worker; the Replay tail for
  from/retry) binding MessageContext.of(e, clock.instant().plus(flow.timeout())); clock = runtime.clock() at build time (no Runtime
  captured). Send: within = MessageContext.current().remaining(clock) when bound → limit.call(within, send); unbound → call(send).
- core FlowDefinition: `timeout()` from flow key `delivery.timeout` (duration > 0, default PT30S); the old 13-arg ctor delegates.
- core TargetLimit: `<T> T call(Duration within, Supplier<Future<T>> send)` waits ≤ min(maxWait, within); within ≤ 0 → a request that
  must wait is refused at once (retryable NackException "…the message's deadline has passed", counted in refused, no timer); a free
  permit is still granted; a deadline-bounded refusal says "…waited <within> until the message's deadline". call(send) = call(maxWait, send).
- flottila-schemas flow.schema.json: `delivery.timeout` (ISO duration string), optional.

## Acceptance (D-088)
- runtime `store.Retention` (final, no interface): `Retention(Pool, Clock, Timer, Config)`, `record Config(Duration maxAge, Duration
  interval, int batch)` validated; `start()` (first run at once, the next `interval` after a run ends, never overlapping); `Future<Run>
  runOnce()` (virtual thread `flottila-retention`; the timer task only starts it); `Totals totals()`; `Future<Void> close()` (cancels,
  waits for the batch in flight). `record Run(Instant cutoff, Outcome DONE|SKIPPED|FAILED, long messages, long keys, long bodies, long
  bodyBytes, long processedIds, long kept, int batches)`.
- cutoff = clock.instant() − maxAge, fixed per run (never server now()). A message goes only when all its rows are < cutoff, no work row
  (held included) and no dlq row has its id. DLQ rows never deleted.
- Each batch: one `pool.withTransaction`, first statement `select pg_try_advisory_xact_lock(<fixed bigint>)`; false → roll back, run
  SKIPPED (or ends early). Correctness never depends on the lock.
- Phase 1 messages + message_keys (keyset over (created_at, id, step), the cursor passes kept rows so the run cannot stall; keys deleted
  through the existing unique index from the deleted rows' `keys`); phase 2 bodies (< cutoff, no messages row, no work row with the
  message_id, no dlq body_key naming it; `octet_length(bytes)` summed into bodyBytes; orphans included); phase 3 processed_ids (< cutoff
  and no messages row with id = message_id). Each phase repeats until a batch scans fewer than `batch` rows. Designer's SQL in the draft
  is the starting point; the implementer verifies it on PG 17.
- A failed batch: WARNING, the run is FAILED and counted, the next run on schedule. One INFO line per run with the counts.
- NodeConfig keys: FLOTTILA_RETENTION_MAX_AGE (ISO-8601, PT1H..P366D, default P7D), FLOTTILA_RETENTION_INTERVAL (PT1M..P1D, default
  PT1H), FLOTTILA_RETENTION_BATCH (1..10000, default 1000); out of range → refused at start, no value printed beyond the key name and bounds.
- Node: built after restore, started after the admin server, closed before the pool.
- V10__retention.sql: `messages(created_at, id, step)`, `bodies(created_at, message_id, step, part)`, `processed_ids(created_at, scope,
  key_hash)` indexes.
- FIX-35: PgBodies.insert one statement `insert … on conflict (message_id, step, part) do update set created_at = bodies.created_at
  where bodies.bytes = excluded.bytes returning 1` — one row = these bytes, none = other bytes.
- Bench [A]: the node ACK bench (bench/run.sh ack) at c=8, 1 run before (HEAD) and 1 after (with V10), 20 000 msgs + 1 000 warm-up,
  recorded as a short section in bench/RESULTS.md (machine line as P2-08b) — the cost of the indexes, no verdict threshold.

- Replay rows naming an expired original's bodies: accepted (F-20), 409 in P2-07b. A dedupe key ages with its message (F-20).

- Unverified, the implementer checks on PG 17 and reports: ON CONFLICT DO UPDATE … WHERE locks and is atomic; withTransaction rolls
  back on a false lock result only if the code fails the transaction explicitly; octet_length on toasted bytea.

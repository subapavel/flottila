# P2-15 — node lease, self-fencing, in-doubt sends (class C; D-101, D-103) — designer draft + architect decisions

Architect 2026-11-05. Designer draft (2026-11-05), summarised; split into P2-15a [B] and P2-15b [B].

## Design (draft — review at hand-over: V14 schema, claim semantics, keys, header, child ids, fail-stop, core types)
- Store Postgres (Valkey optional, own clock and failure domain, cannot serialise with the claim). 0 statements per message;
  one renew per R per node on a dedicated non-pooled connection (P2-16 reuses it for LISTEN).
- V14: `nodes(node text pk, epoch bigint not null, lease_until timestamptz)` (null = released); `work.doubts int not null default 0`;
  no new index on `work`. Keys FLOTTILA_NODE_LEASE PT30S (> 0, ≤ PT10M), FLOTTILA_NODE_LEASE_RENEW PT5S (≤ lease/4).
- Join (start, one tx): old row `for update`, upsert epoch+1, lease_until = now()+L; own unheld items get
  available_at = greatest(available_at, old_until − L/2). Renew + detect: one statement (renewed?, live count, expired peers);
  release only expired peers, only by a node whose own fence stayed open for the last L (a Postgres outage takes nobody over).
- Claim (CLAIM and fast path share ELIGIBLE): another node's item is claimable only when its holder has no live `nodes` row; TAKE
  adds doubts += (locked_by is not null). A holder with no row counts as gone (leaseExpiryRedelivers unchanged).
- Timing on a monotonic clock handed by Node: s = reading before each renew; on success fenceUntil = max(fenceUntil, s + L/2);
  open = !superseded && now < fenceUntil. Renew updating 0 rows = superseded → fail-stop (injected halt; the process exits).
  Takeover ≥ L/2 after the holder's last possible send start; ≈ L + R.
- Core: `Membership` (join/renew/release; InMemoryMembership core, PgMembership runtime); `NodeLease implements BooleanSupplier`;
  `FencedException` (never retried, never parked, item left unsettled); `WorkQueue.Item.doubts`; InMemoryWorkQueue holder-liveness.
- Fence points: at-least-once `Send` (FlowBuilder:584) after the target permit, before producer.send; FlowWorker before complete,
  completeAndTakeNext, hold; CORE-7 before its batch flush. The attempts token stays the database fence.
- In doubt is derived, nothing written per send: an item handed out again after an unsettled hand-out (doubts+1 in the same TAKE);
  attempts count it (D-055); rerun with the same id, parked past maxAttempts; CORE-14 later adds the schedule.
- Notices (Node.notices :328): "one journal copy …" (until CORE-5), "no other live member"; logged once, admin health, never a refusal.
- P2-15b: http producer sets `x-message-id: e.id()` (replacing a forwarded one; mock records it; sftp has no producer yet);
  split child id `<parent>.<n>` (Split.java:45 today fresh ids); the send bounded by the fence (below); kill -9 ledger.

## Architect decisions (2026-11-05)
1. Derived in-doubt accepted instead of D-101 (4)'s per-send record: a write per send costs a commit round trip on the measured
   bottleneck (bench/RESULTS.md CORE-15 preview); over-reports at most the dead node's in-flight items. D-101 amended (draft).
2. Fail-stop when superseded accepted (k8s / systemd restart the process).
3. A send started before the fence must not outlive it: P2-15b bounds an at-least-once producer send by the fence deadline
   (FIX-118's http part folded in); no deploy refusal.
4. Header `x-message-id`, not renameable in P2-15b (a later per-endpoint option is reversible). Replay.retry's new id → CORE-14.
5. Fenced only for at-least-once runs (sync / at-most-once have no takeover). P2-15 done-when "on the flow's schedule (CORE-14)"
   reads "immediate rerun + maxAttempts park" until CORE-14. The single-copy notice lands here; CORE-5 makes it conditional.
6. Constraint carried to P2-16: an item written leased at intake only when its run slot is reserved.

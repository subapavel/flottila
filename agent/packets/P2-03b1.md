## Facts (designer, file:line)
FakeTimer runs every task on the advancing thread (FakeTimer.java:26, 56-68; FakeClock.java:37-40); in-memory stores complete
synchronously (InMemoryWorkQueue.java:41-57, InMemoryDlq, InMemoryMessageStore); the rest runs on virtual threads (Delivery:200,
FlowWorker:270, MockComponent:237, :334, RequestScope:84); no timed park in main code. Validate's Vertx is closed before any case
(Validate.java:99-108). Deployments dev ctor :197. HTTP answer mapping HttpComponent.java:254-276; sync failure fails the answer and
parks nothing (Delivery.java:30-33, 178-180); retryable Nack → 503; at-least-once failed step parks at once (FlowWorker.java:44-46,
351); attempts = retries after the first (RetryPolicy.java:10, 13). JDK 25 `jdk.management.VirtualThreadSchedulerMXBean`:
getMountedVirtualThreadCount() int, getQueuedVirtualThreadCount() long (architect, observed by reflection).

## Acceptance
- `flottila test <dir>`: Package.problems + Validate's dry build (env `ci`); any problem → printed, no case runs, exit 1. Then every
  `kind: test` document in path order, its cases in order, sequentially.
- Per case: fresh FakeRuntime; one MockComponent per shipped scheme (Main.shipped() schemes); document `mocks` with the case's
  `mocks` replacing an endpoint's entry whole; Deployments dev ctor over in-memory stores and a temp data dir (deleted after);
  the deterministic zip (Deploy.zip, built once) deployed under env `ci`; `send` (body file from the package root, `headers`) via
  mock `ingest` on the flow's from endpoint; settle; evaluate; close the deployment under the driver.
- Virtual time [A]: a platform thread `flottila-clock` owns FakeClock advances. Quiet = two consecutive samples with mounted==0 and
  queued==0 and an unchanged fingerprint (timer schedules+cancels via a CountingTimer, clock, mock record sizes, queue size, DLQ
  rows, answer done). Loop: wait quiet → settled? stop : (flow time ≥ 10 min → FAIL "did not settle: <what>") : advance to the next
  due task (zero advance fires due tasks). Settled = answer complete ∧ queue empty ∧ quiet. 60 s wall guard per case → FAIL.
  Spin with onSpinWait/yield, no sleep.
- mock: `public Future<Ack> ingest(String endpoint, Headers headers, Buffer bytes)` builds the ingress envelope as the consumer would
  (ids, flow and maxBodyBytes from the consumer's cfg) and delivers it through the consumer's handler; for an http-scheme mock it sets
  props METHOD `POST` and PATH from the endpoint's path [A]; no running consumer → IllegalStateException; above maxBodyBytes →
  BodyTooLargeException (case FAIL). Not recorded as sent. `public List<Envelope> delivered(String endpoint)` = consumer-side record.
- http: `public static int status(Ack ack, Throwable failure)` extracted from the answer mapping; the door uses it.
- expect: `status` (that mapping; a from endpoint not http → problem); `steps` = timeline size incl. ingress; `keys` = findByKey finds
  the message; `dlq` = DLQ rows; `retries` = Σ per endpoint (sends of the same message id − 1); `error` = the answer's failure
  message or Nack reason contains the text; `sent.<ep>`: `count` = sends incl. retries, `xpath` + `equals|contains` must hold for every
  send (Expressions.value from Main.shipped().languages), without xpath `equals|contains` on the UTF-8 body. test.schema `sent` entry
  tightened to {xpath?, equals?, contains?, count?} (equals and contains exclusive), additionalProperties false.
- `recorded` / `script` behaviours → a problem line "not implemented yet", exit 1.
- Report (stdout): `PASS <flow>: <case> (flow time <d>)` / `FAIL …`, each failed key `  expect.<key>: expected X, was Y`, a final
  `N cases: P passed, F failed`. No wall time (byte-identical across runs). Exit 0 all pass; 1 any fail, package problem, or no test
  document; 2 usage. `Cli` dispatches `test` (replacing "not yet").
- CI: `bin/flottila test packages/demo` after the validate step. The demo test file passes unchanged (`dlq: 0, status: 503, retries: 3`
  is right for a sync flow).
- [A] The `flottila-clock` thread is a tool thread, not a node executor (F-16 framing). GATE 8 "partner 503 → DLQ" is met by
  invoice-async (P2-06); this row proves the async DLQ path on a cli fixture.

# Q-1 — WorkQueue completion fenced by the attempts token (D-074)

Class C. Designer draft approved by the architect 2026-10-28; decisions marked [A].

## Acceptance
- One `current(seq, attempts)` predicate for renew, hold, complete and the same-key fast path, in both implementations:
  the row exists, is not held, `attempts = token`, `token ≥ 1`.
- `WorkQueue.complete(long seq, int attempts): Future<Boolean>` — true = removed; false = stale (claimed again, held,
  completed or unknown), row left to its holder. The 1-arg `complete(seq)` is removed. A held row is never completed.
- `WorkQueue.completeAndTakeNext(long seq, int attempts, String workerId, Duration lease): Future<Completion>`; nested
  `record Completion(boolean completed, Optional<Item> next)`: next non-null; `!completed` ⇒ next empty (IAE otherwise);
  `static final Completion STALE`, `static Completion done(Optional<Item>)`. Stale: nothing completed, nothing taken.
- renew/hold keep their signatures and gain `token ≥ 1`. Class javadoc: "renew, hold, complete and the fast path act only
  for the current holder (Q-1, D-074)"; complete's "held or not, whoever holds it" goes. All `@since 0.1`.
- Pg: `CURRENT = " where seq = $1 and attempts = $2 and attempts > 0 and held_at is null"`; COMPLETE is a guarded delete
  `returning flow, partition_key`; the fast path stays one transaction: guarded delete, rowCount 0 → STALE (the next-of-key
  claim never runs); null key → done(empty); else CLAIM_NEXT_OF_KEY → done(next). No migration.
- In-memory: `current` gains `a > 0`; complete and fast path check `current` before removing; the eligible() Q-1 divergence
  note is deleted.
- FlowWorker: a complete answering false → one WARNING (message, flow, work item, attempt, worker: "claimed again, held or
  completed meanwhile; left to its holder"), `staleSettles` +1 [A: accessor `public long staleSettles()`, precedent
  Trail.metadataOnly], the round succeeds, never retried. A hold answering false → the existing ERROR says "not held: …"
  and counts. A claim of a seq the worker still runs → `lease.adopt(item)`: token becomes the newer attempts, renewal resumes
  if it was lost, a renew answer for a superseded token is not a loss; settle reads the lease's token.
- [A] A released row keeping its attempts (D-067) is left as is (documented in D-074).

## Mutants the reviewer will name
drop `attempts = $2`, `held_at is null`, `attempts > 0` / `a > 0`; stale fast path → done(empty); in-memory remove before
current(); swapped boolean returns; Completion check deleted; settle uses the claim's item instead of the lease token;
adopt does not resume renewal; superseded false treated as lost; stale complete fails the round or skips the count.

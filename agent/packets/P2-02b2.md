## Acceptance
- Candidates: the immediate subdirectories of the deps dir that hold a readable `package.yaml`, the package's own dir excluded; deps
  dir = `--deps <dir>` (must exist, else usage exit 2), default the package dir's parent. A candidate whose package.yaml does not load
  is ignored. A candidate matches a dependency by name and version; two matching candidates with different content → exit 1 naming
  both directories (as given relative to the deps dir).
- `flottila lock <dir> [--deps <dir>]`: for every dependency declared in package.yaml, the matching candidate's `Package.content`;
  writes `package.lock` (`kind: lock`, direct dependencies sorted by name, the format Package's reader and Schemas.LOCK accept; a
  written lock round-trips through `Package.load(...).lock()`), prints one line per entry `name@version sha256:<hex>`, exit 0. No
  dependencies → a lock with an empty list. A missing candidate → exit 1 `dependency common@1.2.0: no candidate under <deps> (it has
  common 1.3.0 | no package common)`, nothing written (an existing lock untouched). The lock overwrites the previous one.
- `flottila validate <dir> [--env …] [--deps <dir>]` and `flottila test <dir> [--deps <dir>]`: resolve the closure from the candidates
  — each lock entry → its candidate (missing → the message above), content compared: drift → exit 1 `package.lock pins common@1.2.0
  sha256:<a>; candidate <rel dir> has sha256:<b>`; then the candidate's own lock, recursively; a name cycle → exit 1 `dependency
  cycle: a -> b -> a`. Then the closure is deployed leaves-first into the dry-build node (validate) and into each case's node before
  the package (test), so the node's own resolution passes. A package without dependencies behaves exactly as today.
- Messages carry no absolute path. Exit 2 for usage (unknown option, `--deps` without a value or not a directory).

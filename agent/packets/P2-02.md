# P2-02 — `sftp` consumer on Apache MINA SSHD + mock + PollingConsumerContract (D-076, F-15)

Class C (raised from B: public api type, new contract). Designer draft approved by the architect 2026-10-28; decisions marked [A].
Out of scope: the poller lease (P2-02L), dedupe at the save (P2-02D), the sftp producer (Phase 4), `secret://` (P2-04).

## Acceptance
- New module `flottila-components/sftp` (depends on `flottila-api`, Apache MINA SSHD `sshd-core`/`sshd-sftp`; testkit at test
  scope). Confirm the MINA version and every API used (SshClient, ClientSession, SftpClient, ServerKeyVerifier, SshServer,
  VirtualFileSystemFactory, SftpSubsystemFactory, SftpEventListener) with Context7 or `javap` on the resolved jar; record the
  version and the observations in the handback. Licence Apache 2.0 → NOTICE line.
- `public final class SftpComponent implements Component`, `SftpComponent(BlobStore blobs, IdGenerator ids, Timer timer,
  Clock clock)`, scheme `sftp`, wired in runtime `Main` next to http. Nested `public final class SftpConsumer implements Consumer`.
- Props (public `Key` constants on SftpComponent): `sftp.file` (name), `sftp.path` (full remote path), `sftp.mtime`
  (ISO-8601 string), `sftp.fileKey` (`sftp://host:port/path@mtime#bodyHash`). Headers empty. No size prop (`body().size()`).
- Options (configSchema, strict): URI `sftp://host[:port, default 22]/dir`. Required `user`, exactly one of `password` /
  `privateKey` (literal until P2-04), `hostKey` (`SHA256:` fingerprint; a mismatch refuses the session, never accept-all),
  `maxBodyBytes` (integer ≥ 1). Defaults: `glob` `*` (file name, regular files, not recursive), `intervalMs` 10000,
  `maxFilesPerPoll` 100, `minAgeMs` 0 (server mtime vs the injected Clock), `afterSuccess` `delete` | `move` (then `moveTo`
  required), `connectTimeoutMs` 10000, `ioTimeoutMs` 30000; optional `errorDir`, `flow` (as http).
- A round (on a virtual thread the consumer starts; the Timer only fires it; fixed delay after the round ends): list, filter
  (glob, regular, minAge), order by (mtime, name), at most `maxFilesPerPoll`, one file at a time:
  - listed size > `maxBodyBytes` → final refusal without reading (errorDir or skip, below);
  - else stream `SftpClient.read` into `blobs.write(BlobKey.body(id, 0), stream, maxBodyBytes)` via api
    `InputStreamReadStream`; `BodyTooLarge` → final refusal; an IOException ends the round and drops the session;
  - the envelope goes to the handler on its own virtual thread (D-057); the round awaits the answer;
  - `Accepted` or `Reply` → delete, or rename to `moveTo/<name>` (`<name>.<id>` if taken); "no such file" counts as done;
    any other delete/move failure leaves the file for the next round;
  - retryable `Nack`, failed future, a throw or null → the file stays and the round ends (§4 poller pause);
  - final `Nack` / final refusal → move to `errorDir` if set, else leave it and skip path@mtime/size for this consumer's life.
- Lifecycle: `start()` schedules round 0 and completes at once (a partner down never fails a deploy). One SSH session per
  consumer, reused across rounds. `stop()` (D-056): cancel the timer, take no new file, await the answer in flight and its
  delete/move, close the session. `health()` UP only while ≥ 1 consumer runs and no consumer's last round failed to connect/list.
- `producer(cfg)` throws `IllegalArgumentException("sftp has no producer before Phase 4")` (the flow build refuses it).
- MINA's NIO2 I/O pool sized to the minimum the API allows (1–2) [A: transport-internal, D-076]; no pipeline runs on it.
- Move runtime `blob/InputStreamReadStream` (and its test) to `flottila-api` `io.flottila.api` as a public final class with a
  public `(Callable<InputStream>)` constructor, javadoc `@since 0.1`; runtime imports it from api. ArchUnit unchanged.
- Mock: `MockComponent.drop(endpoint, name, Buffer)` and `remaining(endpoint)`; Behaviour key `files: <glob>` (fixtures
  resolved against baseDir, fed at consumer start in name order). Mock consumer rounds every 1 s on its Timer [A], same rules
  (one at a time, removed on Accepted/Reply, kept on Nack/failure which ends the round, final Nack not delivered again).
- [A] sftp may feed sync and at-most-once flows (Reply and Accepted both finish the file).
- Docs are the architect's (done in this task's commit): ARCHITECTURE §7 :239, :245, §13 Phase 4, changelog; D-076; F-15.

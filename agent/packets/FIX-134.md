# FIX-134 — put `warmedUp` in the bench record

Class A. Depends on FIX-128 (done, 9c13830). Small: one production line, one assertion.

## The defect

`NodeBenchMain.java:314` computes `int warmedUp = o.warmup() - warmupFailed;` as a **local**. It
decides how long the warm-up's `settle` waits (`:315`) but never reaches the record, so no test can
see it. `warmupFailed` is already in the record at `:316`; `warmedUp` is the one of the three that is
not.

**Read the row's CORRECTED sentence before you reason about mutants.** The architect's first version
of the row had the surviving mutant backwards. An **overstated** `warmedUp` (drop the subtraction, so
`warmedUp = warmup` = 5 against 2 rows that exist) makes the warm-up `settle` poll to DRAIN and IS
caught — but only by the class `@Timeout` at 300 s, which is slow and names no cause. The mutant that
truly survives is an **understated** one: `warmedUp = 0`, or anything up to the real 2, makes the
warm-up settle return at once while the window's own settle still ends at 42 rows, so nothing
asserts and nothing times out. That is the mutant this row exists to make killable.

## The change (production, implementer only)

`flottila-bench/src/main/java/io/flottila/bench/NodeBenchMain.java:316`: add `warmedUp` to the record
beside `warmupFailed`, which is already there:

    measured = h.measure(warmedUp, admin).put("warmupFailed", warmupFailed).put("warmedUp", warmedUp)

Nothing else. Do not change the computation at `:314`, do not change the `settle` call at `:315`, do
not touch `Harness`.

## The red test (test-author only)

`flottila-bench/src/test/java/io/flottila/bench/NodeBenchMainIT.java`, inside the existing case
`aWarmupWhoseFirstSavesAreRefusedRecordsThatCountAndWaitsOnlyForTheRest`. At `:216` that case carries
a comment FIX-128 left behind:

    // acceptance 2 (warmedUp = warmup - warmupFailed) is unobservable while warmedUp is a local: FIX-134's, not asserted here

**Replace that comment with the assertion it says could not be written**, and keep a one-line note
that FIX-134 made it observable. The fixture is a warm-up of 5 with 3 refusals, so the record's
`warmedUp` must be 2. Assert the value and name it in the failure message, so that:

- `warmedUp = 0`, or any value below the real 2, fails by an assertion that says which number was
  wrong, not by a 300 s timeout. That is the class this row exists to kill.
- `warmedUp = warmup` (5) does NOT. **This bullet said the opposite and was wrong** — struck
  2026-11-14 after the test-author's red hand-back and the FIX-134 review, both of which contradicted
  it. `warmedUp` also drives the warm-up `settle` at `NodeBenchMain.java:315`, which runs BEFORE the
  record is written and which needs 5 distinct `messages` rows when only 2 exist (the 3 refused saves
  are rolled back). Its deadline is DRAIN, 10 min (`:134`), longer than the class `@Timeout` of 300 s
  at `NodeBenchMainIT:37`, so the run dies by timeout and line 218 is never reached. The one way to
  see a 5 caught by the assertion is to overstate the RECORD only, leaving the computation intact
  (`.put("warmedUp", o.warmup())`), which is mutant M3 of this review.

Assert on the record the bench actually writes (the `JsonObject`), not on a local or a log line. The
key is absent today, so the red is an assertion failure on a null or missing value — that is the red
to observe and report, and it must name `warmedUp`.

Do not add a second test case. Do not change any other assertion in that file, and nothing outside it.

# Packet FIX-212 (class A) — the rerun IT waits for the rows the design records, not for a count that holds for an instant

Row: `agent/BACKLOG.md` FIX-212, under MAIN-1. Facts: `agent/work/MAIN-1-scout-2.md`.

## The fault (a wrong expectation)

`StepBodiesIT.aRerunOfAStampingStepKeepsEachAttemptsRowAndAReplayAfterARestartReadsAttemptTwosBytes`
(`platform/runtime/src/test/java/io/rail8/runtime/flow/StepBodiesIT.java:424-453`) waits at :442 for
exactly five `messages` rows of `sb-rerun` ("ingress, stamp of attempts 1 and 2, crash-first and
three (attempt 2's)"). The code records six: attempt 1's crash-first row, outcome FAILED, is written
too (`Recorder` records a throwing step and rethrows; `FlowWorker` closes the trail in `finally`,
for an `Error` as well). `count == 5` holds only between two flushes of attempt 2's rows, so the
test passes when the poll happens to look then and spins out its 20 s otherwise. The expectation
came with FIX-175 (one row per step and attempt) and miscounted; no log in the tree shows the test
passing.

A failed step is recorded — monitoring is the product (ARCHITECTURE §8 write path; D-140: each
attempt keeps its own rows). The row is right; the expectation is wrong.

   test, printed into the failure message, or by a throw-away query) — into
   `agent/work/FIX-212-rows.txt`. Expected: six rows — attempt 1: ingress, stamp OK, crash-first
   FAILED; attempt 2: stamp, crash-first, three OK. **If the rows are anything else, stop and hand

2. The test asserts the rows themselves: the list of (step, attempt, outcome) equals the expected
   six, in order — not a count. A count that is right for the wrong rows must fail.
3. The wait is for the final state and cannot be satisfied by a state on the way to it. In order of
   preference: (a) a signal the fixture already owns — the writer's flush or the trail's close, if
   the test holds the writer — and then one read, no poll; (b) if there is none, the existing
   `until` polls for the whole expected list (equality), and its failure message prints the rows
   found. No new production API for the test's sake; no sleep; the 20 s bound of `until` is not
   raised.
4. The comment at :441-442 names the six rows and FIX-212; the reason for the changed expectation
   goes to the hand-back for the commit message (the test was written under FIX-175).
5. The other uses of `rowsOf` in the class are read: one that waits for a count which a later flush

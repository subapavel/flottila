## Behaviour (two sentences)
Every step of a built flow is wrapped, outermost, in a JFR event `io.flottila.Step` (flow, step, name) that is disabled unless a  [superseded: owner decision 2026-11-03, below]
recording enables it; with `FLOTTILA_CPU_SAMPLING=<period>` the node runs one RecordingStream that matches each `jdk.CPUTimeSample`
of a virtual thread to the innermost step event on that thread containing it, and accumulates per flow and step executions, samples
and CPU (sum of each sample's `samplingPeriod`). The admin endpoint `GET /admin/flows/:flow/cpu` shows it, cumulative since the
sampler started, per node; it is never a per-message figure (`Snapshot.cpuNanos` stays null, Meter and the F-21 tripwire unchanged).

## Shape (approved; the implementer may adjust private details, not names or JSON)
- core `io.flottila.core.record.StepEvent extends jdk.jfr.Event`: `@Name("io.flottila.Step") @Category("Flottila") @Enabled(false)
  @StackTrace(false)`, fields `String flow; int step; String name`; `public static Stage marked(Stage s, String flow, <step config>)`
  — begin on entry, end + commit in `finally` (a failed step commits too); fields set only when `shouldCommit()`. No message id.
- core FlowBuilder: every step stage is wrapped by `StepEvent.marked` as the outermost wrapper, always (also with sampling off);  [superseded: owner decision 2026-11-03, below]
  the start stage (ingress / replay) is not marked. A step's CPU includes its retry, numbering, recording and parking wrappers.
- core `io.flottila.core.record.StepCpu` (pure, synchronized, reads no clock, no JFR): `StepCpu(Limits)`; `sample(long thread,
  boolean virtual, long atNs, long periodNs)`; `step(long thread, long startNs, long endNs, String flow, int step, String name)`;
  `lost(long n)`; `advance(long watermarkNs)`; `List<Row> rows(String flow)` (cpuNanos desc, then step asc); `Totals totals()`.
  Records `Row(int step, String name, long executions, long samples, long cpuNanos)`, `Totals(long samples, long attributed,
  long pending, long unattributed, long platform, long lost, long dropped)`, `Limits(Duration lateness /*2 s*/, Duration
  maxPendingAge /*5 min*/, int maxPending /*65_536*/, int maxIntervals /*131_072*/, int maxRows /*4_096*/)` with `Limits.DEFAULT`.
  Rules: a sample goes to the innermost already-arrived, still-kept step interval of its thread containing it (latest start wins,
  both ends inclusive), else waits pending; an arriving step claims its thread's pending samples in [start, end], counts one
  execution and is kept `lateness` for late samples; platform-thread samples count `platform`, never matched; eviction by stream
  time (`advance`, the newest event time seen), never wall clock; past the age a pending sample is `unattributed`; past a cap a new
  entry is `dropped` (counted). Invariant: samples = attributed + pending + unattributed + dropped (platform counted apart).
- runtime `io.flottila.runtime.node.CpuSampler implements AutoCloseable`: `static CpuSampler start(Duration period, StepCpu into)`
  refuses (IllegalStateException naming F-21/FIX-108) unless `FlightRecorder.isAvailable()` and the OS is Linux; registers
  StepEvent and a drain marker event; RecordingStream with `jdk.CPUTimeSample` (throttle "<ms>ms", stackTrace false),
  `io.flottila.Step`, `jdk.CPUTimeSamplesLost`, the marker; ordered, maxAge PT1M, maxSize 64 MiB; `start()` on a virtual thread
  named `flottila-cpu-sampler` (no third executor); onFlush → `advance`; `Future<Void> drained()` commits a marker and completes on
  the first flush after the stream observed it; `close()` stops the stream. `period()` and `since()` (Instant, from the injected clock).
- runtime NodeConfig: env `FLOTTILA_CPU_SAMPLING` = `off` (default, also when absent) or an ISO-8601 duration in whole ms from
  PT0.001S to PT0.1S; anything else is refused naming the key. `Optional<Duration> cpuSampling()`; existing constructors stay.
  Node starts the sampler before `restore()` when set and closes it after the deployments close.
- runtime AdminServer `GET /admin/flows/:flow/cpu` → 200 `{"flow","sampling":"on","period":"PT0.004S","since":"<ISO>",
  "items":[{"step","name","executions","samples","cpuNanos"}],"totals":{"samples","attributed","pending","unattributed",
  "platform","lost","dropped"}}`; off → 200 `{"flow","sampling":"off","items":[]}`; same auth as the other /admin/flows routes;
  unknown flow → the existing 404 shape.
- Stated error: for a (flow, step) with ≥ 1 000 samples in the window and lost ≤ 5 % of all samples, the estimate lies within
  ±10 % of the step's CPU; below that roughly ±1/√samples (the endpoint shows `samples` and `lost`).

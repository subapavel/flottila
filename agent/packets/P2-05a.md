# P2-05a — local quickstart: start a node, deploy the demo, send a message, read it back

Class B. Owner request 2026-10-28 ("chci testovat poslání zprávy do platformy"). Architect spec.
Scout facts: Main needs FLOTTILA_ENV (dev = non-deployed) and Postgres only (Flyway migrates at start, db/Migrations.java:28);
admin API `PUT /admin/packages/:name` takes a zip (AdminServer.java:238-309); `invoice-sync` listens on 0.0.0.0:8080/in and
sends to http://localhost:8090/echo and /echo-foreign (nothing listens there); no runnable jar, no Dockerfile; compose has
postgres:16 with only V1 mounted as init.sql (Flyway owns the schema).

## Acceptance
- Runnable distribution: `flottila-runtime` `package` also copies its runtime dependencies to `target/lib` (maven-dependency-plugin,
  Apache 2.0) and the jar manifest names `io.flottila.runtime.Main` with a `lib/` class path, so
  `java -jar flottila-runtime/target/flottila-runtime-<v>.jar` starts a node. No shading.
- `deploy/quickstart/Dockerfile`: `eclipse-temurin:25-jre` (pin the tag; confirm it exists), copies the jar + lib built on the host
  (`mvn -B -ntp -q package -DskipTests -pl flottila-runtime -am` first, documented), non-root user, EXPOSE 8080 8081.
- `docker-compose.yml`: drop the V1 init mount (Flyway migrates); add service `flottila` (build deploy/quickstart, FLOTTILA_ENV=dev,
  FLOTTILA_PG_HOST=postgres, FLOTTILA_ADMIN_HOST=0.0.0.0, depends_on postgres healthy, healthcheck on `/health`, ports 8080 8081).
  Existing users of the compose Postgres (bench, NOTES "Build and VM") keep working — check and say.
- Partner echo on :8090 without a third-party image: preferred a package `packages/partner-echo` (a sync flow on :8090, paths
  `/echo` and `/echo-foreign`, replying with a fixed ack or the body) deployed to the same node — only if a sync flow can reply
  without a `to` (confirm in code; if not, a 20-line JDK `com.sun.net.httpserver` echo in deploy/quickstart run as its own
  compose service on the same image). The demo endpoints then reach the echo: inside compose `localhost:8090` is the node itself
  for the package option; for the separate-service option use an env overlay (`environments` in the package) rather than editing
  the demo's dev URLs. Record the choice.
- `deploy/quickstart/deploy.sh <package-dir> [name]`: zips the package as AdminServer expects (layout confirmed from the
  deploy code and its tests) and PUTs it to `${FLOTTILA_ADMIN:-http://localhost:8081}/admin/packages/<name>`; prints the
  answer; exit ≠ 0 on a non-2xx. Uses only `zip`/`curl` (or `jar` from the JDK if zip is absent — say which).
- `docs/QUICKSTART.md` (≤ 80 lines): prerequisites (Docker with compose, JDK 25, Maven 3.9); build; `docker compose up -d`;
  deploy partner-echo (if a package) and demo; `curl -X POST --data-binary @packages/demo/fixtures/sample-invoice.xml
  -H 'Content-Type: application/xml' localhost:8080/in` with the expected answer; `GET /admin/messages`,
  `/admin/messages/{id}`, `/admin/messages/{id}/steps/{n}/body`; a CZK and a foreign invoice; how to stop and clean.
  README links it.

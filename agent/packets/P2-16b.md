## Decision (draft — review at hand-over, D-121 (b))
B1 core `interface WorkSignals { void announce(String targetNode, String flow); }` (null = `*`), two implementations on day 1:
   core `LocalWorkSignals` (in-JVM bus between Workers registries, for tests and single-JVM multi-node) and runtime `PgWorkSignals`.
   Receiving side: a signal for this node or `*` → `workers.wake(flow)` (flow `*` → `wakeAll()`); a signal from this node's own
   sender id is ignored. A worker woken by a signal claims once (the existing wake path, backlog flag set).
B2 PgWorkSignals: one dedicated `PgConnection` (never the pool; PgMembership's pattern), `LISTEN flottila_work`, notificationHandler
   parses `w1 <sender> <target|*> <flow|*>`; any other payload is ignored with one WARNING per distinct prefix. On connection loss:
   reconnect with backoff on the node timer (bounded, finite), and after every (re)LISTEN `wakeAll()` once (a missed event is one
   reconciliation, D-121). Closed in Node.close before the pool.
B3 Sending: NOTIFY never inside a hot transaction. `announce` is called after the commit is acknowledged; the first announce of a
   window sends at once (leading edge, `select pg_notify('flottila_work', $1)` on the pool, autocommit); later announces in the same
   50 ms window are folded into ONE statement at the window's end (distinct payloads, `select pg_notify('flottila_work', p) from
   unnest($1::text[]) p`; above 64 distinct payloads fold to `w1 <sender> * *`). A failed send logs one WARNING and is dropped (the
   reconciliation covers it). Window on the injected timer.
B4 Live sources now: (i) a keyed completion that leaves the key's next row on another body_node → announce(that node, flow) — the
   COMPLETE / next-of-key turn returns the next row's body_node when it cannot claim it; (ii) admin release → local workers.wake(flow)
   plus announce(row's body_node or *, flow); (iii) ENQUEUE_FROM written plain because its ref is on another node → announce(ref's
   node, flow) after the commit. Spill and expired-peer events: the WorkSignals call site exists, wired for CORE-5 (no live case).
B5 Reconciliation: the 1 s tick becomes a reconciliation claim every PT30S, its first one offset by `floorMod(hash(flow), 30 s)` so
   flows of one node do not claim together. start() still claims once; the lease-end wake and chain-end backlog claims stay.
B6 Idle silence: an idle node with started flows sends, over 5 minutes, only its membership renewals and one reconciliation claim
   per flow per 30 s — no NOTIFY, no other statement.
B7 Constants (window 50 ms, reconcile PT30S, fold cap 64), no env keys until P2-16c. ArchUnit unchanged: WorkSignals and
   LocalWorkSignals in core (JDK only), PgWorkSignals in runtime.
B8 Docs: ARCHITECTURE §4 Pickup paragraph (events, reconciliation, reconnect), §7 WorkQueue/Node rows, changelog 3.6; F-30 status.

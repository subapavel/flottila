Class **[A]**. This is reading plus a decision per site. It is **not** a redesign, and it is not a licence
to sweep the codebase again: F-30's addendum already bounded the family, and that bound is the finding.

## Why this exists

`docs/findings/F-30.md` settled that D-049 (d)'s "never an escaped exception" means **every throwable**,
and its addendum measured the pattern across all 165 `catch (` clauses in `flottila-*/src/main/java`.
Most resolved by reading. A short list did not, because each needs one question answered that a grep
cannot answer. This task answers them, one at a time, and leaves nothing on the list.

**The outcome of this task is a verdict per site, not necessarily a code change.** A site that is already
right earns a comment saying why, so the next sweep does not re-examine it. A site that is wrong earns a
row of its own with a red test — this task does not widen anything itself.

## The one question per group

**The seven in `Deployments.java` all turn on the same structural question**, and answering it once for
each is the bulk of this task: *does this catch run inside the cleaning `catch (Throwable)` at `:826`, or
inside the rollback `catch (RuntimeException | Error)` at `:927`?* If it runs inside either, an `Error`
escaping it is already caught one frame out, the deployment is already cleaned up or rolled back, and the
site is **right as it stands** — the verdict is a comment naming the enclosing catch, not a change.
Answer it by locating each site's enclosing `try`, not by proximity in the file: a site can sit textually
between `:826` and `:927` and belong to neither.

**`Retry.java:44`** is a semantic question, not a structural one: what does the class javadoc near `:25`
mean by "failure"? If retrying an `Error` is wrong on purpose — and for `OutOfMemoryError` it plainly is —
then the catch is right and the javadoc should say so. If the javadoc promises to retry anything that
fails, the javadoc and the code disagree and that is a finding.

**`Parking.java:49`** is the hardest and F-30 deliberately left it here: *should a step's own `Error` be
parked at all?* `:59` and `:86` are already FIX-142 and are **out of scope here**. Do not pre-empt that
task. If your answer to `:49` changes what FIX-142 should do, say so and stop — that is mine to decide.

**`AdminServer.java:405`** needs the same reading as `:586`, which already has its intent written down
("An Error is the caller's (500)"). Does `:405` serve the same contract?

## What a verdict must contain, per site

One short block each, nothing more:

- the file and the line, **as you found it**, plus the catch clause quoted verbatim;
- the question, answered, with the specific evidence — for the `Deployments` seven, the line of the
  enclosing `try` and which outer catch owns it;
- the verdict: `RIGHT AS IS` (and the comment text to add), `WRONG` (and the one-line change plus the
  case that would pin it, for a new row), or `NOT THIS FAMILY` (and why it translates nothing);
- for `:1682`, whether it should have been in the F-30 sweep, since its absence means the sweep's count
  was short.

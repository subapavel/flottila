# Packet FIX-213 (class A) — the replica start test reads the journal's bytes at a moment it controls

Row: `agent/BACKLOG.md` FIX-213, under MAIN-1. Facts: `agent/work/MAIN-1-scout.md` section 2.

## The fault

`platform/runtime/src/test/java/io/rail8/runtime/journal/ReplicaStartTest.java`,
`theStartRoomCheckCountsTheReplicas`: after `Journal a = holder(files, max)` the test compares
`a.bytes()` with the sizes of the segment and replica files on disk. `Journal.bytes()` counts the
header of the next segment from the moment its pre-open begins, before its file exists — a
reservation, by design (`Journal.preopen`, its javadoc: "its header counts from now, before its file
exists"); the file is created later on a virtual thread (`Journal.attempt`). The comparison is
therefore true only if that thread has already created the file: BASE-1 runs 2 and 3 found 3514
against 3465 on disk — the 49 bytes are `format.headerLength()` — and run 1 passed. The row's
suspect, the disk's usable space, is ruled out: the room check itself (the lines above) passes and
uses the fake `SpaceFiles`.

Not a product fault: the reservation is the documented accounting. The test reads at a moment it
does not control.

## Acceptance

1. The test compares `a.bytes()` with the files on disk only after the pre-open that the start began
   has created its file, and it learns that from a signal — a latch or a future that one of the
   test's own fakes completes when the file is created (the test passes `files`, a
   `JournalFreeSpaceTest.SpaceFiles`, and its rows; read how `Journal.createFile` reaches them) —
   never from a sleep or a poll against a deadline. The equality stays exact; it is not replaced by
   a range or by a set of allowed values.
2. No production file changes and no new production API. If no existing seam lets the test learn
   that the pre-open's file exists, stop and say so in the hand-back with what you read; do not add
   one, and do not loosen the assertion instead.
3. A comment of at most three lines at the wait says why it is there (the header is counted from
   the pre-open's start; FIX-213). Every other assertion of the test and every other test of the
   class is unchanged. The module's test count is unchanged.
4. Show the wait is what makes the test deterministic: once, with a delay injected through the same
   fake before the file's creation (in the test only), the old comparison placed before the wait
   fails with the 49-byte difference and the new one passes; restore and report both.

Test-only: the test-author edits the test (a wrong expectation about when the bytes are on disk,
the reason in the commit message); there is no implementer step.

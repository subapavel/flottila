## Decision (architect, D-126 — the audit schema and the actor source: draft, review at hand-over)
- L1 No restore: a lost body can never be read again (BodyLostException, D-105); the only resolution is discard.
- L2 `GET /admin/work/lost` (token, paged like /held): each lost row with seq, flow, message id, partition key, lost_at,
  and `blocks` = rows of its key behind it (the barrier made visible); /held rows gain the same `blocks` field.
- L3 `POST /admin/work/:seq/discard` (token): deletes the row only while `lost_at is not null`, keyed rows under the
  key's advisory lock (the keyed-complete rule, D-121 (a)), and in the same transaction inserts one `audit` row; then
  wakes the flow locally and announces the key's next row like a release (D-121 (b)). 200 with the audit id; 404 for an
  unknown or non-lost seq (nothing deleted, nothing audited); 400 for a non-number.
- L4 V16 `audit(id bigserial, at timestamptz, actor text, action text, subject text, detail jsonb)`, append-only (no
  update/delete path in code). Actor = request header `X-Flottila-Actor` (trimmed, ≤ 128 chars, else refused 400),
  absent → `unknown`; detail holds flow, message id, partition key, lost_at and the remote address. The actor is
  self-declared under the shared admin token — stated in the docs, not presented as authenticated.
- L5 Docs: ARCHITECTURE §7 WorkQueue row (lost rows and discard), §9 audit sentence, changelog; D-126; F-29 F7.2 row done
  at the commit. FIX-141 does not build `onFailure: block` (still refused, F-32).

## Red tests (test-author)
- PgWorkQueue IT: a lost head keeps its successor unclaimable; discard deletes it and writes exactly one audit row in
  the same transaction (a failing audit insert leaves the row); then the successor is claimable; discarding a leased,
  held or unknown row deletes nothing and audits nothing.
- Admin IT over real PG (LostBodyAdminIT-style, ACCEPT_LOSS fixture): GET /admin/work/lost lists the head with

- No sleeps; red observed.

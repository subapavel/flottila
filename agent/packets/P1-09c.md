# Packet P1-09c — admin write routes and restore (D-057 c, D-067)

Designer draft approved by the architect 2026-10-27. Split into three tasks; P1-09c is done when c1, c2, c3 are.
Library calls: Vert.x `Router.post` is not used in the code yet — verify with javap beside the `get`/`put` AdminServer uses.

## c1 [B] — held items and release (no dependency)

- core `WorkQueue`: `record Held(Item item, Instant heldAt)`; `Future<Page<Held>> held(Optional<String> after, int limit)`
  (seq order, cursor = seq, bad limit/cursor → IAE); `Future<Boolean> release(long seq)` — true only for a held row; clears
  `held_at`, `locked_by`, `locked_until`, keeps `attempts`. Pg: `update work set held_at=null, locked_by=null,
  locked_until=null where seq=$1 and held_at is not null`; the listing uses V5's `work_held` index. Both implementations.
- routes: `GET /admin/work/held?limit&after` → 200 `{items:[{seq, messageId, flow, step, partitionKey, attempts, heldAt}],
  next|null}`; `POST /admin/work/{seq}/release` → 200 `{seq}`, 404 unknown or not held, 400 seq not a long. Token required.
- tests first: InMemoryWorkQueueTest + PgWorkQueueIT — heldListsOnlyHeldRowsInSeqOrderAPageAtATime,
  heldRefusesABadLimitOrCursor, releaseClearsHoldAndLeaseKeepsAttempts, releaseOfAnUnheldOrUnknownSeqIsFalse,
  aReleasedRowIsClaimedBeforeTheRowsBehindItsKey; jqwik property heldRowsBlockTheirKeyUntilReleased.
  FlowWorkerTest — aReleasedExhaustedItemIsParkedAtStepOneOnItsNextClaim. AdminServerWorkTest — heldPagesWithHeldAt,
  releaseIs200Then404, aSeqNotANumberIs400, workRoutesNeedTheToken.

## c2 [C] — replay and retry routes (after c1 for the AdminServer constructor; GATE check 7)

- core `Replay`: overloads `from(id, n, replayId)`, `retry(id, replayId)` (old forms use `ids.next()`); after its pre-checks
  `admission.tryAcquire(bodySize)`, permit released after the trail closed; `Future<Void> close()` refuses new runs and closes
  its own producers once runs in flight ended. Pre-run refusals throw `ReplayRefusedException extends IllegalArgumentException`
  with `Reason {UNKNOWN_MESSAGE, NO_DLQ_ROW, STEP_OUT_OF_RANGE, NOT_RECORDED, METADATA_ONLY, STEP_BEYOND_FLOW, TOO_LARGE,
  BUSY, CLOSED}`; anything the run throws is the outcome, never a refusal.
- `FlowBuilder.replay(flow, baseDir, Delivery)` shares the delivery's Admission (package-private `Delivery.admission()`); the
  2-arg form gets its own Admission from the same limits — no unbounded path.
- Deployments builds the replay in `flow()` (failure → problem line), keeps it on `Flow`; `Optional<Replay> replay(flowId)`
  for RUNNING flows only; closes with the worker (not awaited in a swap; awaited up to stopDeadline in `close()`, WARNING).
- routes (AdminServer gains `WorkQueue`, `IdGenerator`): `POST /admin/messages/{id}/replay?from=n`,
  `POST /admin/dlq/{id}/retry`. 200 `{id, replayOf, from, outcome:"COMPLETE"}`; a failed run 502 `{id, replayOf, from,
  outcome:"PARKED"|"FAILED", error}`. Order: 400 (from missing/not int/outside 1..steps) → 404 (no timeline / no DLQ row) →
  409 (flow not RUNNING here; a retry of this id already running on this node) → 422 (step n−1 unrecorded or metadata-only;
  parked step beyond the redeployed flow; body above the byte budget) → 429 + `retry-after: 1` (no permit) → run. 409 for a
  body gone by retention is reserved for P2-07. Retry delivered but row removal failed → 500 `{error}` naming the new id.
- browser guard (D-069): every `/admin/**` request with an `Origin` header, or `Sec-Fetch-Site` other than `none`, is 403
  `{error}` before the token check — tests AdminServerBrowserGuardTest: aCrossOriginPostIs403WithoutReachingTheRoute,
  aSecFetchSiteOtherThanNoneIs403, aCurlStyleRequestWithoutOriginPasses, theGuardRunsBeforeTheTokenCheck (GET, PUT and POST).
- threading: `from`/`retry` run only on a virtual thread (AdminServer `offload`); never on the event loop (the trail-close
  join deadlocks), never `executeBlocking` (third executor). No isVirtual guard.
- tests first: ReplayTest — fromWithAGivenIdRunsAsThatId, everyPreRunRefusalNamesItsReason,
  aReplayHoldsAFlowPermitUntilItsTrailClosed, noRoomIsBusyAndRunsNothing, closeRefusesNewRunsAndClosesProducersAfterTheLastRun.
  FlowBuilderTest — aReplayInFlightMakesTheConsumersNextDeliveryARetryableNack. AdminServerReplayTest —
  replayIs200WithIdReplayOfFromOutcome, aFailedRunIs502Failed, aParkedRunIs502Parked, badFromIs400, unknownIs404,
  notRunningIs409, unrecordedOrMetadataOnlyIs422, noRoomIs429WithRetryAfter, theRunIsOnAVirtualThread,
  retryIs200AndTheRowIsGone, aConcurrentRetryOfTheSameIdIs409, aRetryWhoseRowRemovalFailsIs500NamingTheNewId.
  DeploymentsProducersTest — aSwapClosesTheReplacedReplayOnceItsRunEnded, closeClosesEveryReplaysProducers.
  NodeIT (GATE 7) — replayFromStep3IsANewMessageMarkedReplayOf, partnerDownParksAndRetryDeliversOncePartnerIsBack.
- docs at its commit: F-11 + §6 edit (replay runs the version deployed now), F-8 closed in §6, D-057 c amended (422 not 409).

## c3 — deployment record in Postgres, archive in S3, restore (owner option A, D-070) — split c3a/c3b

Owner's decision 2026-10-27 (git-first): Postgres keeps only the record; the archive is stored once in S3 keyed by its
sha256 and fetched + verified on restore. No bytea, no lowered package bound (`FLOTTILA_MAX_PACKAGE_BYTES` stays 1 B..1 GiB).
Designer draft approved by the architect 2026-10-27. Library calls to verify with javap before use: `RequestBody.fromFile`
(sdk-core 2.56.0), `DefaultCredentialsProvider` (auth 2.56.0); `getObject` → `Files.copy` as TieredBlobStore does.

### c3a [C] — the record, the archive store, the write path (after c2)

- `V7__deployments.sql`: `deployments(package text primary key, version text not null, revision text, archive_sha256 text not
  null check (archive_sha256 ~ '^[0-9a-f]{64}$'), deployed_at timestamptz not null)`; one row per package, shared by the pool.
- runtime.deploy `record DeploymentRecord(String name, String version, Optional<String> revision, String archiveSha256,
  Instant deployedAt)` — deployedAt truncated to µs. `interface DeploymentStore { Future<Void> save(DeploymentRecord);
  Future<List<DeploymentRecord>> list(); }` (upsert by package, list sorted by name): `PgDeploymentStore(Pool)`,
  `InMemoryDeploymentStore`.
- `interface ArchiveStore { void put(String sha256, Path archive) throws IOException; void fetch(String sha256, Path target)
  throws IOException; }` — blocking, on the virtual thread; sha256 not 64 lower-case hex → IAE; `put` always PUTs (idempotent);
  `fetch` replaces the target, a missing object → `NoSuchFileException` naming the key, any SdkException → IOException naming
  bucket and key. `S3ArchiveStore(S3Client, bucket, prefix)` key `<prefix>/archives/<sha256>.zip`; `DirArchiveStore(Path dir)`
  temp file in dir then ATOMIC_MOVE to `<dir>/<sha256>.zip`.
- Deploy write order: unpack → check → build without problems → `archives.put` (before anything stops; failure → `Kind.FAILED`
  500 "archive sha256:<hex> not stored: <cause>", cleaned up, old version runs) → phase A → phase B → `records.save(..).await()`
  (the commit point; failure: first deploy 500 + cleanup, redeploy `rollBack` with problem "the deploy record was not written:
  <cause>") → listing → prune. Orphan objects are kept; nothing deletes archives in Phase 1.
- Config (`NodeConfig`, IAE names the key): `FLOTTILA_ARCHIVE_STORE` s3|dir (default dir), `FLOTTILA_ARCHIVE_DIR` (default
  `<dataDir>/archives`); s3 needs `FLOTTILA_S3_BUCKET` + `FLOTTILA_S3_REGION`; optional `FLOTTILA_S3_ENDPOINT` (absolute http(s)
  URI), `FLOTTILA_S3_PATH_STYLE` (false), `FLOTTILA_S3_PREFIX` (`flottila`); `FLOTTILA_S3_ACCESS_KEY`/`_SECRET_KEY` both or
  neither (neither → SDK default chain); secret redacted in toString. New components `Archives archives, Optional<S3> s3`; the
  8-arg constructor stays (dir default).
- `Node.start`: after the mock check, before Postgres/S3 — a deployed env refuses `dir` and an `http:` endpoint (ISE). One
  S3Client built as S3TierIT does; closed last in `close()` and on a failed start.
- `Deployments` new constructor `(…, DeploymentStore, ArchiveStore)`; the old 11-arg one uses InMemoryDeploymentStore +
  DirArchiveStore, so existing test classes stay untouched.
- tests first: `MigrationsIT` v7DeploymentsHoldsTheRecordAndNoBytes (+ count 6→7 here and in `BenchMainIT`: wrong expectations,
  reason in the commit). Contract `DeploymentStoreContract` (PgDeploymentStoreIT, InMemoryDeploymentStoreTest): aSaveIsListed,
  aSaveReplacesThePackagesRow, listIsSortedByName, deployedAtRoundTripsToTheMicrosecond, anAbsentRevisionIsEmpty. Contract
  `ArchiveStoreContract` (S3ArchiveStoreIT on LocalStack, DirArchiveStoreTest): aPutArchiveFetchesByteForByte,
  aSecondPutOfTheSameSha256IsQuiet, fetchOfAnUnknownSha256IsNoSuchFileNamingIt, aKeyNotLowerHexSha256IsRefused,
  fetchReplacesTheTarget; S3 only theObjectKeyIsPrefixArchivesSha256Zip, anUnreachableEndpointIsAnIOException.
  `NodeConfigTest` archiveStoreDefaultsToDirUnderTheDataDir, s3NeedsBucketAndRegion, s3KeysComeInPairs,
  anUnknownArchiveStoreIsRefused, theSecretKeyIsRedacted. `NodeTest` aDeployedNodeRefusesADirArchiveStoreBeforePostgres,
  aDeployedNodeRefusesAPlainHttpS3Endpoint. `DeploymentsRecordTest` theArchiveIsStoredBeforeAnythingStops,
  aFailedPutIs500AndTheOldVersionRuns, aDeployIsRecordedOnlyOnceItsFlowsStarted,
  aFailedRecordRefusesAFirstDeployAndRollsBackARedeploy, aRefusedDeployWritesNoRowAndKeepsItsObject.
- docs at its commit: D-070; CLAUDE.md "keyed by message id + step" scoped to message bodies (owner's option A).

### c3b [C] — restore at node start (after c3a; done-when RestoreIT)

- `Deployments.restore()` blocking, under the deploy lock, before the admin port opens; `records.list()` failing throws and
  fails `Node.start`. Per row by name: fetch into a temp file in `.incoming` (always deleted) → sha256 compare → install in
  RESTORE mode (no 403, no put, no row write; deployedAt and revision from the row; a flow whose start fails is FAILED, the
  others run). A package refused whole (fetch failed, sha256 differs, unpack refused, problems) is FAILED with an ERROR log;
  `DeployedPackage` gains `State state` (RUNNING|FAILED) and `List<String> problems`, a FAILED one has no flows or files;
  `/admin/packages` items gain both. A data-dir IOException fails the start. A PUT over a FAILED package is a first deploy.
  S3 down at start → every package FAILED, /health DOWN, recovery by a restart or a PUT (no retry; see CONSIDER-1).
- `Node.start` order: config → spool → pool → blobs → components → mock + archive refusals → synchronous_commit → migrate
  V1..V7 → stores + archive store → Deployments → restore → AdminServer. Health check `deployments` DOWN while any package or
  flow is FAILED (names in detail, wire status only, D-057 a). Admin start failure: Deployments closes first, then stores,
  pool, S3 client.
- tests first: `DeploymentsRestoreTest` restoreStartsEachPackageWithoutAPutOrARow, restoreRunsInADeployedEnvWhereAPutIs403,
  aFlowThatDoesNotStartOnRestoreIsFailedTheOthersRun, aMissingArchiveIsAFailedPackage,
  anArchiveWhoseSha256DiffersIsAFailedPackage, aPackageWithProblemsIsFailedTheOthersRun,
  restoreListsRevisionAndDeployedAtFromTheRow, restoreLeavesIncomingEmpty, restoreThrowsOnlyWhenRowsCannotBeRead,
  aPutAfterAFailedRestoreRestartsTheFailedFlows, aPutOverAFailedPackageIsAFirstDeploy. `AdminServerDeployTest`
  packagesListStateAndProblems. `NodeTest` restoreRunsBeforeTheAdminPortOpens, healthIsDownWhileAFlowOrPackageIsFailed,
  anAdminStartFailureStopsTheRestoredFlows. `RestoreIT` (Postgres + LocalStack)
  aRestartedNodeWithAnEmptyDataDirResumesQueuedAtLeastOnceWorkWithoutAPut, aDeletedObjectRestoresAFailedPackageAndHealthIsDown
  (leased items run after the D-055 lease: an `until` bound on a fake or real deadline, no sleep).
- docs at its commit: §9 "Deployment mechanics" + changelog; D-057 c amended (V7, S3 not bytea); D-063 "Listing" amended
  (FAILED also means restore could not start it); F-12 (S3 becomes a start dependency of a deployed node, not of the hot path).

## Rejected
A `Run` result record; bytea archive in Postgres; nodes fetching the git revision; archives through BlobStore; package name in the S3 key; HEAD-then-skip put; server-side checksumSHA256; deleting superseded archives; failing node start when S3 is down; replay as a Delivery flight; re-enqueueing a replay; replaying the pinned old version; archive only on
disk; per-node rows; a chunk table now; all-or-nothing package at restore.

## Owner points at hand-over
F-11; rows shared by the pool; 502 for a replay's own failure; /health DOWN for one FAILED flow (vs degraded); no archive deletion in Phase 1; a deployed env refuses `dir` and plain-http S3; SDK default checksums vs SeaweedFS (P2-05); a replay of an at-least-once flow holds a permit and the admin request through its backoff;
the retry guard is node-local (two nodes can retry one row); a crash between phase B and the row write restores the previous
version, a committed-but-reported-failed save restores the new one.

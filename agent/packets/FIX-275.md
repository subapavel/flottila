# FIX-275 - `/retry` refuses while a work row of its id is unsettled (class C)

Row: `grep -n "^| FIX-275 " agent/BACKLOG.md`. Finding `docs/findings/F-57.md`, decision D-162 (5).
Class C: the work queue's lease path and concurrency (`AGENTS.md`). The design is D-162's - the designer and the advisor,
twice - so there is no second draft: if the code contradicts the design, stop and say so.

A park is two writes: the DLQ row commits, then the run's work row is removed (the settle). When the park is interrupted
or the settle fails, the DLQ row stands beside a leased work row of the same id. The restart statement locks the DLQ row
and never reads `work`, so an operator's `/retry` in that window inserts a second work row of the id: the message is
delivered twice, or delivered and parked again. This row adds the guard and nothing else of D-162.

The defect is read in the code, not staged. The first job of this row is to stage it: the second work row (acceptance
1) and both outcomes (acceptance 2). If the three ITs are green on today's code as written, stop and say so: the finding
is then wrong and the architect corrects it.

## The one new type (named here so that a red test can name it)

`dev.rail8.core.queue.UnsettledException extends RuntimeException` with `String messageId()` and `long seq()`: a restart
was refused because the work row `seq` of that message is still there. It lives until FIX-276 turns it into a value of the
act's answer. A test that does not compile because this type does not exist yet is a valid red (`AGENTS.md`).

## Acceptance

The scenario of acceptances 1 and 2, in `DlqRestartIT`: an at-least-once flow; the partner fails the first attempt so that
the worker parks the message at attempt 1; a queue decorator at the store boundary fails that item's settle once, so its
work row W1 stays leased beside the DLQ row. Then the restart is called as `/retry` would call it for that row.

**The lease's clock.** A Postgres lease runs on the database clock: `claim` compares `locked_until` with `now()`
(`PgWorkQueue.java:150`), so the fake clock never frees W1. Where a case below says W1's lease has passed, the test moves
it past on the database clock - `update work set locked_until = now() - interval '1 second' where seq = <W1>`, as
`PgWorkQueueContractIT.expireLeases` does (:49-50) - never by a sleep; the fake clock drives only the worker's own
timers. A case whose old row is never handed out again proves nothing: each outcome case asserts that W1 was claimed
again (its `attempts` is 2, or the row is gone) before it asserts the outcome.

1. **The second work row** - `aRetryBeforeTheParksSettleLandedIsRefused` (a bound of 2 hand-outs, a final NACK): the
   restart fails with `UnsettledException` naming W1's seq; the DLQ row is still there; the id has exactly one work row.
   Today it answers `true`, the DLQ row is gone and the id has two work rows - that is the red, and the hand-back quotes
   the failing assertion.
2. **Both outcomes.** Each case tolerates the first restart's answer (refused, or `true` as today) and asserts the end
   state only, so that its red on today's code is the outcome, not the answer:
   - `aMessageRetriedBeforeItsParkSettledIsAcceptedByThePartnerOnce` (a bound of 2 hand-outs, a final NACK at attempt
     1): after the restart the partner accepts; W1's lease is moved past on the database clock; the worker runs until
     nothing is left to claim. Expected: the partner accepted the message exactly once. Today: twice - the retry's row
     delivers and W1, handed out again within its bound, delivers too. The case asserts nothing about the DLQ row: with
     the guard W1's rerun delivers and the row stays (CONSIDER-28, not this row's).
   - `aMessageRetriedBeforeItsParkSettledDoesNotComeBackAfterItsDelivery` (a bound of 1 hand-out): after the restart the
     partner accepts; W1's lease is moved past on the database clock; the worker runs until nothing is left to claim; a
     second restart is issued only if the first was refused, and the worker runs again. Expected: the partner accepted
     the message exactly once, the failed list has no row of the id and the id has no work row. Today: the first
     restart's row delivers, W1 comes back past its bound and parks the message again unsent - delivered, and in the
     failed list.
3. **Both queues, the contract** (`WorkQueueContract`, run by the in-memory and the Postgres contract classes):
   - a restart while a work row of the id and flow exists fails with `UnsettledException` carrying that row's seq and
     writes nothing - the row count of the id stays one, and on Postgres the DLQ row stays;
   - the same when the restart is given no key (`null`) and the existing work row is keyed: the probe is by id and flow
     only when no key is given, never `partition_key is null`;
   - Postgres only, `PgWorkQueueRestartIT` (beside `aRowWhoseKeptRefIsGoneFailsBlobNotFoundAndChangesNothing`, :92):
     `aRowWhoseKeptRefIsGoneBesideAnUnsettledWorkRowIsRefusedAsUnsettled` - the restart fails with `UnsettledException`,
     not `BlobNotFoundException`, and changes nothing: the guard is read before the lost body (acceptance 6).
4. **Where the guard sits** (Postgres): in the RESTART statement, after the DLQ row lock - a work row with the id and the
   flow, and with the key when one is given; the delete and the insert happen only when there is none. One statement, as
   today; the keyed path stays under the key lock it already takes. A refused restart writes nothing: no DLQ delete, no
   work row, no ref copy.
5. **The route** - `AdminDlqRestartTest`: when the queue answers `UnsettledException`, `/retry` answers 409 with an
   `{error}` that names the message id and the work item's seq and says it is not settled yet; the text names no other
   route (`namesNoOtherRoute`); nothing is woken or announced.
6. The order of answers is unchanged where no work row exists: 404 for no DLQ row, 409 for a lost or missing body, 202
   otherwise. A lost body beside an unsettled row answers the unsettled refusal (the guard comes first).
7. Every existing restart case stays green unchanged (`DlqRestartIT`, `PgWorkQueueRestartIT`, `WorkQueueContract`,
   `FlowWorkerRetryTest`, `AdminDlqRestartTest`, `AdminDlqRestartIT`, `NodeIT`).
8. Javadoc that describes the restart says what it now refuses: `WorkQueue.restart`, the RESTART statement,
   `InMemoryWorkQueue.restart`.
9. Coverage no lower on core and runtime; whole reactor green.

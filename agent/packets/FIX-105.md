# FIX-105 — compose: a network-namespace holder for the node and the echo

Class A. Architect spec 2026-10-30 from GATE run 1 (target/GATE-stack.log, check 5) and the scout (5505b0f).

## Facts
deploy/compose/docker-compose.yml: `flottila` publishes 127.0.0.1:8080/8082/8081 (:151-154); `echo` (:163-174) runs PartnerEcho on
8090 with `network_mode: "service:flottila"`, depends_on flottila healthy. Root docker-compose.yml: same (:44-46, echo :56-66 with
`network_mode: "service:flottila"`, depends_on flottila). The demo partner endpoints call http://localhost:8090 (packages/demo
endpoints/partner-*.yaml:7). Observed: after `docker kill -s KILL` of the node and `docker compose up -d`, the echo stays up and
healthy but the node gets "Connection refused localhost:8090" until `docker compose restart echo` — the echo kept the dead
container's namespace.

## Acceptance (both compose files)
- A service `netns` holds the network namespace: the already-used image `eclipse-temurin:25.0.4.1_1-jre-noble` (no new image, no new
  licence), command `sleep infinity`, a healthcheck, publishes every port the node published (same 127.0.0.1 bindings), carries the
  network alias `flottila` on the default network so every existing `http://flottila:8081` reference (deploy service, CI stack job,
  READMEs) keeps working unchanged.
- `flottila` and `echo` both use `network_mode: "service:netns"` and publish no ports themselves; flottila depends_on netns healthy
  (plus its existing deps), echo depends_on netns healthy and flottila healthy as today.
- Killing and restarting the node leaves the echo reachable on localhost:8090 without an echo restart; stopping the echo leaves the
  node healthy. Container names used in the docs (`docker compose exec flottila`, `docker kill …-flottila-1`) stay valid.
- READMEs / QUICKSTART: one line each only where they name ports or the namespace.

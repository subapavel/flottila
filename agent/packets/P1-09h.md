# P1-09h — Durable at-least-once bodies (D-058, D-061, F-6). Designer draft 2026-10-27, approved by the architect with the ARCH decisions below.

## Acceptance
- `persist(k)` completes only after its insert has committed. Witnesses: another session sees the row, and a fresh `TieredBlobStore` (new spool dir, key and pool) reads the bytes.
- `Delivery.atLeastOnce` answers Accepted only after `Future.all(persist, record)`, then the enqueue.
  - A failed or throwing persist → a retryable Nack with the cause, nothing enqueued, the permit released.
  - A persist still pending at the save timeout or at the stop deadline → nothing enqueued, even if it completes later.
- Sync and at-most-once deliveries never call persist.
- No code path issues a DELETE on `bodies`; deletion belongs to the retention job, P2-07.
- ARCH: `Node.start` refuses to start (one `flottila:` line, exit 1 through Main) unless Postgres `synchronous_commit` is `on`, `remote_write` or `remote_apply`. Test: `NodeIT.aNodeRefusesAsynchronousCommit`, which sets it `off` for the node's role or database.

## Shapes
- api `Future<Void> BlobStore.persist(BlobKey key)`: abstract, no default.
  - Idempotent for a key that is already durable.
  - Fails `BodyTooLargeException` above the durable bound, `IllegalArgumentException` for a key with nothing stored, and `IllegalStateException` when the store has no durable tier.
  - Never deletes.
- core `Delivery` calls `e.body().store().persist(e.body().key())`. A persist that throws becomes a failed future. Ingress has no attachments. FlowBuilder is unchanged.
- runtime `public final class PgBodies(Pool pool, long maxBytes)` in `runtime.blob`, with 1 ≤ maxBytes ≤ 64 MiB (otherwise IAE).
  - Package-private: `insert(BlobKey, Buffer)` (on conflict do nothing, autocommit), `Future<Optional<Buffer>> select(BlobKey)`, `Future<Boolean> exists(BlobKey)`, `long maxBytes()`.
  - It has no delete statement.
- runtime `TieredBlobStore(Config, Hasher, PgBodies)` is a new public constructor; the 2-argument constructor has no durable tier. `persist`:
  - S3 body → completes at once.
  - Memory or spool body:
    - size > maxBytes → `BodyTooLargeException`; nothing written, the body stays local.
    - otherwise read, then insert, then `remove(k, s)` from the index and release the budget, all before the future completes.
    - the spool file is unlinked afterwards on a virtual thread; a failure is a WARNING log.
  - Key not in the index → `exists` decides: done, or IAE.
  - `read`, `open` and `whole` fall back to `select` on an index miss; `open` is lazy; a missing row → IAE.
  - `location` reports local tiers only.
  - Test seam: `afterRelease(Consumer<BlobKey>)`.
- The first durable bytes win for a key (as snapshots do, D-044). No local cache after persist.
- Node builds the Pool before the blob store, then `new PgBodies(pool, blobs.durableMax())`, and closes the pool on every failed start path. Verify with javap that `PgBuilder.pool().build()` opens no connection.
- testkit `InMemoryBlobStore.persist`: succeeds for a stored key, and `persisted(k)` is then true; other keys → IAE. New `DurableBlobStoreContract extends BlobStoreContract`.
- DDL `deploy/postgres/V6__bodies.sql`:
  ```sql
  create table bodies (message_id text not null, step int not null, part text not null,
                       bytes bytea not null, created_at timestamptz not null default now(),
                       primary key (message_id, step, part));
  alter table bodies alter column bytes set storage external;
  ```
  (Use the runtime's migration folder if it differs; check where V1–V5 live.)

  - `>` → `>=` on the bound

## Acceptance (D-087)
- package.yaml `dependencies: [{name, version}]`, version = the exact version pattern (no ranges); each name once; never the package itself.
- package.lock at the package root (YAML): `schemaVersion: 1, kind: lock, dependencies: [{name, version, content: "sha256:<hex>"}]`,
  direct dependencies only, sorted by name; new lock.schema.json `urn:flottila:schema:lock:1`, unknown keys refused. `content` = SHA-256
  over UTF-8 lines `flottila-package-content 1` then `file <path> <sha256>` per regular file sorted by `/`-path (same data as
  DeployedPackage.files); one implementation in flottila-schemas used by the node (and the CLI in P2-02b2). In this row the lock is
  written by hand in tests. Package reads package.lock (not a document kind for the walk).
- Spelling `stylesheet: common:xslt/to-ubl.xsl` / `schema: common:xsd/x.xsd`: `^[a-z][a-z0-9-]{0,63}:` before the first `/`; only
  direct dependencies visible; an include inside a dependency file stays in that dependency; `common:` inside XML stays a refused
  non-file URI. Document the colon collision (a root file named with `:`).
- api StepResources: new last component `Map<String, Path> dependencies`; existing 7- and 8-arg constructors pass `Map.of()`; `file("n:p")`
  confines to that dependency's dir; resolve(baseUri, ref) and absolute paths confined to whichever root holds the base/path; reads
  reported as today. FlowBuilder `dependencies(Map)` setter like `reads`. Both CompiledFiles copy the map.
- FlowHash: a dependency read hashes as `file <dep>:<path> <sha>`; a flow reading nothing from a dependency hashes exactly as today.
- Deployments.check (deploy and validate), before build: available = each RUNNING package's current version + every version a record
  pins ([A] a FAILED package's version is not available); every lock entry matches name, version, content; follow each resolved
  version's own lock to the closure; the package-name graph must be acyclic.
- DeploymentRecord gains `List<Pin(name, version, archiveSha256)> dependencies` = the closure; V9 `deploy/postgres/V9__deployment_dependencies.sql`:
  `alter table deployments add column dependencies jsonb not null default '[]'::jsonb`, saved in the existing upsert (commit point
  unchanged). In-memory store too.
- Prune never removes `packages/<dep>/<sha>/` while any record pins it (also during restore, whatever the order). Restore unpacks a pin
  from the ArchiveStore by sha if absent locally; a pin that cannot be fetched → the package FAILED naming the pin.
- GET /admin/packages adds `content` and `dependencies: [{name, version, content, archive, direct}]`. [A] no message stamp.
- Refusals, all 422 INVALID, no absolute path in any line (wording binding, the test-author may tighten):
  Package.problems: "package.yaml declares dependencies [common], package.lock is missing" · "package.lock pins common 1.2.0,
  package.yaml declares 1.3.0" · "package.lock pins <x>, which package.yaml does not declare" · "dependency 'common' is declared twice" ·
  "dependency cycle: invoice -> invoice" · "<file>: flow '<id>' step '<s>' stylesheet 'nope:a.xsl' names package 'nope', which
  package.yaml does not declare" · "… leaves package common". Node: "dependency common@1.2.0 is not deployed on this node (it has common
  1.3.0 | no package common)" · "dependency common@1.2.0 has content sha256:Y on this node, package.lock pins sha256:X" · "dependency
  cycle: a -> b -> a" · "… stylesheet 'common:xslt/x.xsl' does not exist in common@1.2.0".
- Off-node (this row): validate/test resolve against an empty node → a package with dependencies exits 1 "not deployed on this node";
  demo has none (CI unaffected). P2-02b2 adds `--deps` and `flottila lock`.

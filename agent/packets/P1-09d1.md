# P1-09d1 task packet (designer draft 2026-10-26, approved by the architect with the decisions marked ARCH)

Split (ARCH): P1-09d1a [C] = package validation building blocks; P1-09d1b [C] = Deployments, admin routes, Node wiring, NodeIT. d1b depends on d1a.

## Shapes
- runtime `NodeConfig.Blobs(long treeLimit, long memoryTier, long memoryBudget, long durableMax)`: env `FLOTTILA_BLOB_DURABLE_MAX`, 1 B..64 MiB, default 1 MiB.
- core `public FlowBuilder versions(Map<String,String> extra)`: merged into the existing `flow=<id>@<v>` versions written by Recorder, Parking and Replay; a `flow` key → IllegalArgumentException.
- schemas `Package`: `manifest()`, `endpoints()`, `flows()` (Map<String,JsonObject> copies), `Path flowFile(String id)`, and `List<String> problems()`.
  - `problems()` reports each document against its kind's schema (`<file> at '<ptr>': msg`), then duplicate endpoint or flow ids (load overwrites them today), then `crossCheck()`.
  - Also `static Schemas.Report Schemas.check(String schemaJson, JsonObject doc)`, for a component's `configSchema()`.
  - ARCH: `Package.load` stopping at the first file that does not parse is accepted; the 422 names that file.
- runtime package-private `io.flottila.runtime.deploy.PackageArchive.unpack(Path zip, Path into, long max)` with ZipFile. It refuses (→ 400):
  - a file that is not a zip;
  - more than 10 000 entries;
  - actual uncompressed bytes above 4×max;
  - an entry that is absolute, duplicate, or resolves outside the target after normalize.
- runtime `io.flottila.runtime.deploy.Deployments` (final, no interface):
  - constructor `(NodeConfig, Runtime, List<StepFactory>, List<Expressions>, MessageStore, Dlq, WorkQueue, Meter)`; the Runtime goes only into `new FlowBuilder`;
  - `long maxPackageBytes()`, `Path incomingDir()`, `List<DeployedFlow> flows()`, `void close()`;
  - `DeployedPackage deploy(String name, Optional<String> revision, Path archive)`: blocking, on a virtual thread, throws `DeployRefusedException(Kind{BAD_REQUEST,INVALID,CONFLICT,STOPPING,FAILED,FORBIDDEN}, String error, List<String> problems)`;
  - `DeployedPackage(name, version, Optional revision, archiveSha256, List<String> flows)`;
  - `DeployedFlow(id, pkg, packageVersion, Optional revision, flowVersion, delivery)`.

## Deploy order
1. A bad name (not `^[a-z][a-z0-9-]{0,63}$`) or a bad revision (not `[0-9A-Za-z._-]{1,64}`) → 400.
2. ARCH: `config.deployed()` → 403 `{error:"manual deploy is non-production only (ARCHITECTURE §9)"}`. The control plane deploys production later.
3. The node is closing → 503. Another deploy holds the tryLock → 409. The name is already deployed → 409 (until P1-09d2).
4. Unpack into `.incoming/<uuid>`, then ATOMIC_MOVE it to `<dataDir>/packages/<name>/<sha256hex>/`; an existing directory there is replaced.
5. Validate. A flow id owned by another package → 409. Then start. Any refusal deletes the directory.

## Validation
All problems are collected into one 422 `{error, problems}`, and nothing starts until every check passes:
- `Package.problems()`, or a file that does not parse;
- the manifest name differs from the URL name;
- non-empty `dependencies`;
- a scheme with no component on the node;
- scheme `mock` while `deployed()`. With ARCH step 2 this cannot be reached via PUT; keep the check in `Deployments` anyway and test it with a dev config where `deployed()` is forced through env `prod` plus a direct `deploy(...)` call. ARCH correction: since `deploy()` itself refuses with 403 when deployed, the mock check is unreachable — drop it and drop the test `aMockSchemeIsRefusedOnlyWhenDeployed`. The Node already refuses mock bindings in a deployed env (P1-09b);
- endpoint `config` with `environments.<env>.config` laid over it (keys replaced) failing `configSchema()`;
- an `in` endpoint that sets `flow` or `maxBodyBytes`;
- one `from` endpoint used by two flows;
- `FlowDefinition.from` refusals;
- an at-least-once flow with `maxBodyBytes > durableMax` (D-058; the bound from the first commit, made durable by P1-09h);
- build failures of `delivery`, `worker` or `component.consumer(cfg, handler)`.

The deploy sets the consumer options `flow` (the flow id) and `maxBodyBytes` (the flow's limit). Demo partner endpoints gain `maxBodyBytes: 1048576`, and their urls become `http://localhost:8090/echo` and `/echo-foreign`.

## Start
- At-least-once: the consumer goes over `worker.pollingAfterAccept(delivery)`; call `consumer.start()`, then `worker.start()`, with workerId = nodeId.
- Other flows: the consumer goes over `delivery`.
- A failed start stops every flow of the package (`worker.stop`, `delivery.stop(ZERO)`, `consumer.stop`), deletes the directory, and answers 500 `{error:"flow 'x' did not start: …"}`.
- Versions: `package=<name>@<version>`, plus `revision` only when one is given.

## Admin and Node
- `AdminServer` gets a 6-arg constructor with `Optional<Deployments>`; the 5-arg one delegates with empty, and the routes are then 404.
- PUT `/admin/packages/{name}?revision=`:
  - content-length above max → 413 without reading the body;
  - otherwise pause the request, pipe it with back-pressure to a temp file in `incomingDir()`, and count; at max+1 → 413 and the file is deleted;
  - success → 200 `{package, version, revision|null, archive:"sha256:<hex>", flows}`;
  - refusal kinds map to 400 / 422 / 409 / 503 / 500 / 403.
- GET `/admin/flows` → 200 `{items:[{id, package, packageVersion, revision|null, flowVersion, delivery}]}`, sorted by id, not paged. Both routes need the token.
- `Node` builds `PgWorkQueue` and `Deployments`. `close()` runs `deployments.close()` first, then admin stop, store flush and pool, each in a finally.
- `deployments.close()`:
  - refuses new deploys (503) and waits for a running one;
  - then for every flow in parallel: `worker.stop()`, then `Future.all(delivery.stop(stopDeadline), consumer.stop())`;
  - rethrows the first failure after all have stopped.
  - Known limit: worker items still in flight are not awaited (P1-09e); their lease re-runs them.

## Architect decisions after the d1a implementation (2026-10-26)
- F1 → d1b: the Package accessors `manifest()`, `endpoints()`, `flows()` and `flowFile(id)` are added in d1b, together with schemas `PackageTest` cases for them. d1b's allowed paths include the schemas test folder for those cases.
- F2 → d1a round 2: `crossCheck` runs only over documents that passed their schema, so `problems()` never throws on a document the schema refuses.
- F3 → d1a round 2: add `flottila-runtime/.../deploy/package-info.java`, in the style of the other runtime packages.

## d1a review round 1 FAIL → round 3 (2026-10-26)
- Package.crossCheckFlow (:133–:137): a schema-valid step with a mistyped `endpoints` or `endpoint` (step `additionalProperties: true`) throws ClassCastException. Add type guards so that `problems()` never throws on any document; a mistyped value is a problem line naming the file.
- PackageArchive: "nothing written" is pinned for every refusal (size, duplicate). Also decided:
  - an IOException in the read-only inflate pass (e.g. EOFException on a truncated entry) is an IllegalArgumentException;
  - a file/directory clash (`a` plus `a/b`) is refused in the check pass before any write.
- Problem lines name the package-relative path, never an absolute path; that includes requireFile.

## Carried into d1b from the d1a review round 2 (non-blocking)
- A file entry that resolves to the target itself (`.`, or `a/..` without a trailing slash) is refused in the check pass (`target.equals(root)`), giving 400 and not 500.
- `stylesheet`/`schema` given as a non-string: assert "must be a string" (P1-09f step options against configSchema covers the rest).

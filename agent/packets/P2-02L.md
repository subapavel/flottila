## Acceptance
- runtime `io.flottila.runtime.lease.PollerLeases` (interface; two implementations day 1):
  `Future<Boolean> hold(String key, String owner, Duration ttl)` — takes a free/lapsed key or renews one `owner` holds; true = held for
  ttl from the call. `Future<Void> release(String key, String owner)` — deletes only if `owner` holds it. No fencing token.
- `ValkeyPollerLeases(Redis)`: hold = one EVAL (`GET`; absent → `SET k o PX t` 1; equal → `PEXPIRE k t` 1; else 0); release = EVAL
  compare-and-`DEL`. Key `flottila:poller:<pkg>/<flow>/<endpoint uri as written>`, value `<nodeId>#<n>` (n per Deployments).
  Vert.x Redis API (`Redis.createClient`, `RedisAPI.eval`, `Response.toInteger`) by javap on vertx-redis-client 5.1.10 (version from
  vertx-stack-depchain); its licence read from the resolved pom `<licenses>` and stated in the hand-back (must be Apache 2.0/EPL).
- `InMemoryPollerLeases(Clock)`: same semantics on a map, expiry on the injected clock (never "always held").
- package-private `deploy.LeasedConsumer implements Consumer` (leases, key, owner, ttl, renewEvery, timer, clock, first,
  `Supplier<Consumer> fresh`): `start()` completes at once and schedules tick 0. Each tick on its own virtual thread, fixed delay; t0 read
  before `hold`; `hold` bounded by renewEvery on the injected Timer. true → validUntil = t0 + ttl, start an inner consumer if none runs
  (first the given one, later `fresh.get()`; a stopped consumer is never restarted). false → stop the inner consumer now. Failure/timeout →
  inner keeps polling only while now < validUntil, stopped at validUntil; next tick at min(renewEvery, validUntil − now). Never polls
  without a confirmed hold. No new inner starts before the old one's stop settled. Inner start failure → WARNING, release, retry next tick.
  `stop()`: cancel the next tick, await a tick in flight, stop the inner consumer (awaits the in-flight file, D-056), then release; a
  failed release is logged (lapses after ttl); an instance that never held releases nothing.
- Deployments: in `consumers()` :1123, `polls(from)` inside the same try; true → wrap in LeasedConsumer. New longest constructor takes
  `PollerLeases`; the existing ones default to `new InMemoryPollerLeases(clock)`. Swap/rollback/close need no new code (phase A's stop
  releases, phase B's tick 0 takes it). Class javadoc: a leased consumer's start failure after the deploy is a WARNING + retry.
- api `Component.polls(EndpointConfig)`: default false, `@since 0.1`; javadoc: answered from cfg alone; when true the node runs a
  consumer only while it holds the endpoint's lease, so `consumer(cfg, handler)` may be called again after the previous one stopped.
  sftp overrides true. http, mock: default false [A].
- NodeConfig: `FLOTTILA_VALKEY_URI` (redis:// or rediss://, optional, password redacted in toString/logs), `FLOTTILA_POLLER_LEASE_TTL`
  (PT30S), `FLOTTILA_POLLER_LEASE_RENEW` (PT10S); both > 0 and ≤ PT10M, 2×renew ≤ ttl, else refused. The 11-arg canonical constructor
  stays as an overload. Node: URI set → ValkeyPollerLeases (client closed in closeStores); else InMemoryPollerLeases + one WARNING at start.

## [A] decisions
- Open 1: mock `polls` false (one process; a deployed node refuses mocks; `flottila test` send cases unaffected).
- Open 2: Done-when restated: ≤ ttl + renew after the holder's last hold, never while its validity runs (BACKLOG updated).
- Open 3: a node without `FLOTTILA_VALKEY_URI` → in-memory + WARNING, not a refusal (single node legitimate; two such nodes duplicate,
  never lose).
- Open 4: standby visibility → FIX-96; no Valkey check in `/health`.
- Expensive to reverse, marked draft in D-083: `Component.polls` + its re-call sentence; Valkey key/value and scripts; env keys.

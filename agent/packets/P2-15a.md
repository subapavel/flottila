## Acceptance
1. V14: `nodes(node text primary key, epoch bigint not null, lease_until timestamptz)`; `work.doubts int not null default 0`; no
   new index on `work`. Keys FLOTTILA_NODE_LEASE PT30S (> 0, ≤ PT10M), FLOTTILA_NODE_LEASE_RENEW PT5S (> 0, ≤ lease/4), parsed by
   NodeConfig only; out of range → IAE naming the key.
2. Core `Membership` (join / renew / release; InMemoryMembership in core, PgMembership in runtime on a dedicated non-pooled
   connection), `NodeLease implements BooleanSupplier` on an injected monotonic clock and Timer: fenceUntil = max(fenceUntil,
   s + L/2) on each successful renew (s = reading before the request); open = !superseded && now < fenceUntil; a renew updating 0
   rows = superseded → injected halt (fail-stop); a node releases expired peers only if its own fence stayed open for the last L.
3. Claim (CLAIM and CLAIM_NEXT_OF_KEY): another node's item is claimable only when its holder has no live `nodes` row (a holder
   with no row = gone); TAKE sets doubts = doubts + (locked_by is not null). Join reruns this node's own unheld items only after
   the previous incarnation's fence (available_at = greatest(available_at, old_until − L/2)). FIX-130's bounded plan kept.
4. `FencedException`: never retried, never parked, the item left unsettled. Fence checked by the at-least-once `Send` before
   producer.send, and by FlowWorker before complete, completeAndTakeNext and hold. Sync / at-most-once flows unfenced.
5. In doubt derived (no write per send): `WorkQueue.Item.doubts`; a rerun counts as an attempt (D-055), same id, parked past
   maxAttempts. 0 statements per message added; one renew per R per node.
6. Notices: "one journal copy: this node's at-least-once items wait for it while it is down (D-101 (5))" (until CORE-5) and
   "no other live member"; logged once at start, admin health, never a refusal.

Readings decided: (1) live = not released (lease_until not null); an expired unreleased row still renews and blocks a claim.
(2) join opens the fence at s + L/2; closed before join. (3) a fresh node releases nobody for its first L. (4) Renewal.live counts
the renewing node. (5) at most ONE renew in flight (finite): a tick while one is outstanding sends nothing; the fence keeps counting
from the outstanding send; a test needing overlapping renews is a wrong expectation → report it, do not change it. (6) an
operator-released row (locked_by null) is taken without a doubt. (7) halt once; no renew after supersession.

## Behaviours
- NodeConfig: FLOTTILA_TARGET_MAX_CALLS (1..10000, default 16), FLOTTILA_TARGET_MAX_WAIT (PT0.001S..PT5M, default PT5S),
  FLOTTILA_TARGET_LIMITS = `<target>=<n>,…` (n in 1..10000; each key canonicalised with the Component.target format: lower-cased,
  default port filled for http/https/sftp; a malformed entry or a duplicate key after canonicalisation refuses the start naming
  the entry). Overrides carry the default maxWait. Never unlimited.
- Node builds one `Targets` from it; Deployments passes it to every FlowBuilder it builds (deploy :1378-1382, restore :922, and any
  other FlowBuilder it constructs), so two packages naming one partner and the old/new version of a flow during a redeploy share
  one limit.
- AdminServer `GET /admin/targets` (same guards as /admin/*): 200 `{items:[{target, maxCalls, maxWaitMs, inFlight, waiting,
  refused}]}` sorted by target; unshared limits not listed.
- NodeBenchMain sets the echo target's override to the bench concurrency (so c=64 is not capped at 16); bench/RESULTS.md unchanged.
- HttpComponent.target refusal wording: "option 'url'" when url is set, else "the endpoint URI" (one case).

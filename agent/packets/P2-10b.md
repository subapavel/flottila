## Behaviour (additions to flottila-sim; append-only codes for Action, FaultKind, Check)
- Actions, each with its prediction:
  - SEND_AMO: Accepted; the run happens once with no retry after the ACK, and a failure parks nothing durable beyond what the at-most-once path records today (read Delivery:205).
  - SEND_ALO with a dedupe key: Accepted names the first id for that key.
  - DUPLICATE: a lost ACK; the same key and payload are re-sent; predicted Accepted with the first id and no second effect.
  - REPLAY_FROM(id, n): `Replay.from(id, n, replayId)` with an explicit replayId; its last output hash equals the recorded one.
  - RETRY_DLQ: the DLQ row goes away and the new message is final.
  - PARTNER_OUTAGE: a window of ticks in which every partner call is refused; predicted retries, then a DLQ row at the `to` step.
  - DROP_REPLY: the effect is done, the reply is lost, and the same id reruns; ONE_ID allows the rerun (D-049 b).
- The dedupe path runs over a sim `DedupingIntake` double, because SequentialIntake refuses a key (D-084). PgIntake processed_ids comes in P2-10d.
- New checks:
  - ONE_ID_PER_DEDUPE_KEY, per unit: at most one id per dedupe key.
  - REPLAY_YIELDS_RECORDED, at each replay: no REMOVED_BY_RETENTION refusal, and the hash equals the recorded one.
  - Both join SimSelfTest's FLOORS.
- Carry-overs from the P2-10a review:
  - Separate compared counts per ADMISSION_BOUNDS part (flow limit, bytes, worker runs), each with its own floor, so the floor proves that sends arrived at the limit.
  - Sync PREDICTED pins the number of partner calls.
  - The SimSchedulerTest probe javadoc says it spins on thread state on purpose; the harness never does.
- New broken worlds, each failing its exact check set within the per-push seeds:
  - IDEMPOTENT_CHECK_REMOVED: the intake decorator passes dedupeKey null → {ONE_ID_PER_DEDUPE_KEY}.
  - LOST_REPLAY_BODY: a BlobStore decorator acknowledges the persist of step ≥ 1 keys and drops the object → {REPLAY_YIELDS_RECORDED}.
  - If World has no BlobStore seam, add one (test-author spec, implementer code).
- Nightly job `sim-fuzz` in .github/workflows/ci.yml beside `mutation`:
  - Runs on schedule and workflow_dispatch, needs build, times out after 40 min.
  - Steps: `mvn -B -ntp -q install -DskipTests -pl flottila-sim -am`, then `mvn -B -ntp -pl flottila-sim test -Psim-fuzz -Dsim.fuzz.base=${{github.run_id}} -Dsim.fuzz.minutes=25 -Dsim.ticks=5000`.
  - SimFuzzTest is excluded by default and included only by the profile, so it is never a skipped case.
  - Failures go to target/sim-failures.tsv in the pin format and are uploaded as an artifact.
  - For a local check, `-Dsim.fuzz.minutes` accepts a fraction (e.g. 0.05).

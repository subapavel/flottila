# FIX-144 — readiness and liveness endpoints (review F4.4, F-29) [B]

## Today
GET /health (AdminServer.java:326, health() :511-521) awaits three checks (postgres `select 1`, deployments, journal) with no
deadline (FIX-23) and knows nothing of the fence or a drain: a fenced or closing node answers UP until admin.stop (Node.close
:435-469 stops deployments, then the lease, then admin). No /ready or /live route exists.

## Decision (architect, D-123 reversible)
- R1 `GET /live`: no token, answers 200 `{"status":"UP"}` while the admin server runs. It reads no store, awaits nothing,
  touches no PG — liveness is "the process and its event loop answer". Kubernetes startupProbe and livenessProbe use it.
- R2 `GET /ready`: no token, 200 `{"status":"UP","checks":{...}}` or 503 `{"status":"DOWN","checks":{...}}`; checks, each
  "UP"/"DOWN": `lifecycle` (UP only once Node.start finished and before Node.close began), `fence` (NodeLease open),
  `journal` (UP only when the journal is neither failed nor in outage — DEGRADED counts DOWN: saves would fail),
  `deployments` (DOWN while any package or flow is FAILED, the /health rule). Every input is an in-memory read answered on
  the request — no await, no PG round trip (the open fence already says PG renewals succeed within half a lease), so it
  needs no deadline.
- R3 Drain: Node.close marks the lifecycle closing as its first act, before deployments.close stops the listeners, so
  /ready answers 503 while the consumers still accept and drain. admin.stop stays last.
- R4 /health is unchanged (its deadline is FIX-23). Probe inputs reach AdminServer through the existing HealthProbe wiring
  pattern (a small readiness record of suppliers built in Node), never by AdminServer holding Node or Runtime.
- R5 Docs: ARCHITECTURE §9 next to the deployments-health sentence, changelog entry; D-123 in DECISIONS.

## Red tests (test-author)
- AdminServerTest: `liveAnswers200WithoutReadingAnyCheck` (probes that throw or never complete are not called);
  `readyIsDownNamingEachFailedCheck` (one case per check DOWN, body names it; all UP → 200); `readyAnswersWithoutAwaiting`
  (a never-completing /health check does not delay /ready); /live and /ready need no token while /admin does.
- NodeIT (real wiring): `fencedNodeIsNotReadyButRemainsLive` (fence closed through the node's real lease path, e.g. the
  fake clock past half a lease with renewals failing → /ready 503 fence DOWN, /live 200);
  `drainDropsReadinessBeforeListenersStop` (hold Node.close mid-drain — a consumer delivery held — /ready 503 lifecycle DOWN
  while the listener still answers and /live 200); `journalFailedNodeIsNotReady` if the fixture can fail-stop the journal;
  `liveDoesNotTouchPostgres` (PG unreachable or pool closed → /live 200).
- Red observed before hand-back; no sleeps; a fake clock drives the lease.

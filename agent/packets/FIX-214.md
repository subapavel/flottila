# Packet FIX-214 (class A) — the frame relay names the side that closed, whichever pump sees it

Row: `agent/BACKLOG.md` FIX-214, under MAIN-1. Facts: `agent/work/MAIN-1-scout-2.md`.

## The fault (a test fixture's)

`PeerProtocolTest.aLinkPausedByAnAbandonedConsumerIsClosedAfterATimeoutAndItsReadsFail` asserts at
:767 that the relay saw the link closed by the dialer (node-b, whose watchdog closes a link that
gives no answer). The claim is right; the relay's answer is a race. In
`platform/runtime/src/test/java/dev/rail8/runtime/journal/peer/FrameRelay.java`, `Connection.pump`
(:144-172) attributes every `IOException` to `fromSide` — the side the pump reads from — also when
the exception comes from the write to `to` inside `pipe.forward(out, frame)`. When node-b closes,
the pump B->A reports `DIALER` and the pump A->B, if it is writing to node-b's closed socket,
reports `LISTENER`; `close(side)` keeps the first (:173-177). Failed in BASE-1 run 2 and in `ci`
run 193 (`expected: <DIALER> but was: <LISTENER>`).

No production code is at fault and none changes: the watchdog closes the link and its reads fail,
which :766 and :769 assert.

## Acceptance

1. `FrameRelay` attributes a close to the side whose socket closed: a failure of the read of `from`
   (EOF, reset) names `fromSide`; a failure of the write to `to` names the side written to; a frame
   the relay itself refused still names `RELAY`; an interrupt keeps today's answer. Both pumps give
   the same answer for one close.
2. Red first, at the relay's level, not by repeating the flaky test: a test of `FrameRelay` (in the
   relay's own test class if there is one, else a new `FrameRelayTest` beside it) in which only the
   write failure can report — for example the direction dialer->listener held by the relay's own
   pause with a frame in flight, the dialer's socket closed, the listener sending until the relay
   closes — and `closedBy` must be `DIALER`. Observed red before the fixture changes, green after.
   Use the relay's existing controls and plain sockets; no sleep — wait on `awaitClosedBy`.
   If the relay's controls cannot build a deterministic red, stop and hand back what you tried:
   the architect decides whether the code-level argument and run 193 stand as the red.
3. `PeerProtocolTest` is not edited: :767 stays and is now deterministic.
4. Nothing under `src/main` changes. No test is removed or disabled.

Test-only task: the test-author writes the red test and the fixture change (a fixture is the
test-author's); there is no implementer step.

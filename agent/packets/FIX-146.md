# FIX-146 — Postgres TLS with CA and hostname verification (review F9.1, F-29) [B]

## Today
All PG options come from NodeConfig.Pg (NodeConfig.java:216, keys :407-409) through Node.connectOptions (Node.java:346-348):
pool (:209), membership (:242), LISTEN (PgWorkSignals, :274) — no SSL mode, no trust. Flyway migrates over JDBC
(Node.java:234, Migrations.java:40) with a bare `jdbc:postgresql://host:port/db` URL. Against a TLS-only Postgres the node
cannot connect; against a plaintext one a remote password and every payload cross the network unencrypted.

## Decision (architect, D-124 reversible — review at hand-over: the keys and the loopback default)
- T1 `FLOTTILA_PG_SSL_MODE` ∈ `disable` | `verify-ca` | `verify-full`; any other value refused at start naming the key.
  Default: `disable` when `FLOTTILA_PG_HOST` is loopback (`localhost`, `127.0.0.1`, `::1`), else `verify-full`. No
  `require`/`prefer` (TLS without verification is not offered: it gives no protection against an active attacker).
- T2 `FLOTTILA_PG_SSL_ROOT_CERT`: path of a PEM CA bundle. Required for `verify-ca`/`verify-full`; missing or unreadable →
  start refused naming both keys (fail closed — never a silent fallback to plaintext or to an unverified link). Not a
  secret; the password stays redacted in NodeConfig.toString.
- T3 One source: Node builds the Vert.x options (SslMode, PemTrustOptions over the CA, hostname verification on for
  verify-full, off for verify-ca) once and shares them with the pool, membership and LISTEN connections; the JDBC URL
  carries `sslmode=<mode>&sslrootcert=<path>` from the same config. Bench is out of scope (own wiring; note it).
- T4 Docs: ARCHITECTURE §9 next to "TLS with hostname verification everywhere" (Postgres keys and the loopback default),
  changelog row; D-124 in DECISIONS; F-29 F9.1 row "done" at the commit. Compose files that reach PG by a non-loopback
  name set `FLOTTILA_PG_SSL_MODE=disable` explicitly (visible, never implicit).

- PgTlsIT (Testcontainers postgres:17 with `ssl=on` and a pg_hba of `hostssl` only; certificates generated in the test with

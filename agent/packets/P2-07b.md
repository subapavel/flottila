## P2-07b1 shape
- api `public final class BlobNotFoundException extends IllegalArgumentException` (@since 0.1): ctor `(BlobKey key)`, `BlobKey key()`,
  message "no object stored under <key>". Not a Fault. `read` fails with it; `open` throws it or returns a stream that fails with it
  before its first chunk; `persist` fails with it — for any key with nothing stored. Body.whole/open pass it through.
  TieredBlobStore.noObject (:413) returns it (open, durable :407, read :274, persisting :324); the spool-gone ISE stays an ISE.
- api `default Future<Boolean> exists(BlobKey key)`: reads; true, false on BlobNotFoundException, other failures fail.
  TieredBlobStore overrides (index hit → true; no durable tier → false; else `bodies.exists` by primary key, no bytes);
  testkit InMemoryBlobStore overrides (containsKey). BlobStore javadoc :11-12 → "Deletion belongs to the retention job, by age
  (D-088, F-20), never on the hot path, and is not part of this contract; a removed key reads as never written."
- core `ReplayRefusedException.Reason.REMOVED_BY_RETENTION`: Replay.from checks after METADATA_ONLY, retry after STEP_BEYOND_FLOW,
  both before `admit` (no permit held): `if (!blobs.exists(key).await()) throw refused(REMOVED_BY_RETENTION, "the body of step
  <n−1> of message <id> (<key>) was removed by retention")`. A store failure in the check propagates (502), not a refusal. A refused
  retry keeps its DLQ row. AdminServer.refusal: REMOVED_BY_RETENTION → 409.
- AdminServer body(): narrow the IAE catches at :499 and :804 to BlobNotFoundException; the new message above.

## Acceptance
- core `Intake` (package of Delivery [A]): `Future<Void> save(Envelope arrived, Snapshot ingress, String flow, String partitionKey,
  BooleanSupplier abandoned)`; success = body durable, ingress recorded, item queued; failure = no item. `abandoned` asked once, just before
  the enqueue (Sequential) / the commit (Pg); true → nothing queued, the future fails.
- core `SequentialIntake(MessageStore, WorkQueue)`: today's Delivery code moved as is.
- runtime `PgIntake(Pool, TieredBlobStore, PgMessageStore, PgWorkQueue)`: `pool.withTransaction(tx -> body insert → record → item →
  abandoned ? fail : ok)`; provenDurable + release after the commit, before the future completes. A body already durable inserts nothing; a
  body from another store is persisted first (not in node wiring). Seams runtime-internal: `PgBodies.insert(SqlClient,…)`,
  `TieredBlobStore.persistIn(SqlClient,key)` (persist(key) the same path on the pool), `PgBatchSink.write(SqlClient,batch)` reused by
  `PgMessageStore.insert(SqlClient,Snapshot)`, `PgWorkQueue.enqueue(SqlClient,…)`. Confirm `SqlClient` ⊇ Pool, SqlConnection by javap.
- Delivery.atLeastOnce takes an Intake; the store/queue overloads wrap SequentialIntake (DeliveryTest, DeliverySavePropertyTest unchanged).
  FlowBuilder.intake(Intake) defaults to SequentialIntake; Node builds PgIntake and passes it through Deployments. The ingress row leaves the
  BatchingWriter. A failed intake: retryable Nack, permit released, not counted in snapshotWriteFailures [A].
- No SQL schema, wire or api change. Docs done by the architect: D-082, ARCHITECTURE §4/§8 + changelog.

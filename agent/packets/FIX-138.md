# FIX-138 — the DLQ retry keeps the message id (class C; F-29 F4.1, D-045)

Row: agent/BACKLOG.md FIX-138. Follows CORE-14b (d44ea64, D-135 [CORE-14b]). Designer draft 2026-11-12, decided below.

Facts (designer, scout):
- `/admin/dlq/{id}/retry` (AdminServer ~:733-787, Replay ~:134-163) mints a new id, removes the row only after the run (Replay:157), its guard is
  node-local (`retrying`, AdminServer:739). GATE check 7, HANDOVER:53, NodeIT P1-09c2 use `/retry`. `/restart` (CORE-14b) is same-id.
- A second run under one id: `messages` PK (id, step) `on conflict do nothing` (PgMessageStore:55), body_refs first write wins unless GONE
  (TieredBlobStore:162-180); body keys get `~attempt` only when ATTEMPT ≥ 2 (Envelope:90-101), Replay strips ATTEMPT (Replay:258-261).
  So run 2's snapshots are dropped silently — the same as today's worker reruns (D-135) → FIX-175 (filed).

## Decision
P1 One rule: retry keeps the id, replay mints one. Split:
  - FIX-138a (this packet now): `POST /admin/dlq/{id}/retry` becomes the CORE-14b same-id restart handler unchanged (202 {id, attempt}; 404/409/422;
    the 422 texts name `/replay`). `/restart` is removed (404) — nothing outside the repo calls it. `POST /admin/dlq/{id}/replay` is today's
    `/retry` unchanged (new copy from the parked step, replayOf, Admission, D-067 statuses, 503 per D-133; a `from` parameter is 400).
  - FIX-138b (filed, after 138a): the durable copy claim for `/admin/dlq/{id}/replay` (V18 `dlq.copy_id`, `copy_runs`; `Dlq.claim`/`settle`;
    a repeat reuses the copy id with ATTEMPT = run; `/retry` 409 on a claimed row; RESTART `d` `and copy_id is null`), designer §1/§2.
P2 Rows from a replay or parked at step n have no same-id path (`/retry` 422 names `/replay`): accepted; CONSIDER-14 filed.
P3 Draft — review at hand-over (WORKFLOW §6: admin routes change meaning). New D-136 amends D-045, D-057(c)/D-067, D-135 [CORE-14b].
P4 Docs (architect): D-136; §4 :201 and §6 :272; changelog 3.17; HANDOVER :53 (`/retry` = same id, add a `/replay` line) and drafts list;
  F-29 F4.1 status "same-id retry: FIX-138a; copy claim: FIX-138b". GATE.md unchanged (check 7 reads "retry", now same id).

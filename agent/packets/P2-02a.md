# P2-02a — package folders: artifacts by kind in any folder, package-root references (D-060 d, D-078)

Class C. Designer draft approved by the architect 2026-10-28; decisions marked [A]. The CLI tree moved to P2-03.

## Facts (designer, file:line)

PackageArchive.unpack accepts any depth (runtime deploy/PackageArchive.java:32-78); crossCheck resolves a reference against

## Acceptance
- Discovery by `kind`: walk the package in `/`-path order; `package.yaml` at the root = package; `folder.yaml` in a non-root
  folder = folder; any other `*.yaml|*.yml` takes its schema from `kind` (endpoint | flow | test). [A] A YAML without a known
  kind is a problem `<path> at '/kind': …` **unless** a flow or test file references it as a file (then it is a plain file).
  `flows/` and `endpoints/` stay valid as ordinary folders.
- Layout rules in `Package.problems()` (listed first; the deploy 422 at Deployments.java:745 and `flottila validate` share
  them): folder names `^[a-z][a-z0-9-]*$`, ≤ 64 chars, else `<dir>: folder name '<seg>' is not a slug`; deeper than 4 →
  one line on the shallowest offending folder `<dir>: 5 folders deep, at most 4`. File names free.
- `folder.schema.json` (`urn:flottila:schema:folder:1`): `schemaVersion: 1`, `kind: folder` required; `namespace` optional,
  string 1..1024, verbatim (no trim, no case fold); `description` optional string; unknown keys refused. Problems also:
  `folder.yaml` at the root, `kind: folder` under another file name, `package.yaml` below the root, [A] one namespace in
  two folders (naming both `folder.yaml`).
- References are paths from the package root: flow `stylesheet`/`schema`, D-065 `resources`, test `send`/`reply`/`files`.
  XML include/import stays relative to the including file. All confined to the package: `requireFile` resolves against the
  package dir and reports `leaves the package`; Deployments passes baseDir = the package dir (StepResources keeps its shape,
  javadoc only); no 422 line carries an absolute path (strip the package dir from build messages).
- FlowHash v2: line 1 `flottila-flow-hash 2`, the yaml line `yaml <sha256>` without the path. A flow file moved alone is
  unchanged (not swapped); moving its stylesheet and editing the reference is a change.
- Tree: `Package.folders()` → `List<Package.Folder(path, Optional<String> namespace, Optional<String> description)>` (every
  folder below the root, sorted); `Package.artifacts()` → `List<Package.Artifact(path, kind, Optional<String> id)>` (a test's
  id empty), sorted by path. DeployedPackage holds both; `GET /admin/packages` adds `folders:[{path,namespace|null,
  description|null}]` and `artifacts:[{path,kind,id|null}]`; a FAILED package has both `[]`. `files` unchanged.
- Existing packages migrate to root references (the red commit by the test-author changes the test fixtures; the
  implementer changes packages/demo flows, the invoice-async test resource and NodeBenchMain:346).
- Docs are the architect's (done): D-078, ARCHITECTURE §9 sentence + changelog, BACKLOG P2-03 note, FIX-84.

## Mutants the reviewer will name
depth `> 4` → `>= 4` / `> 5` · slug regex unanchored, 64 vs 65 · kind ignored in favour of the folder · references resolved
against the naming file's folder · confinement dropped · baseDir = flowFile.getParent() · yaml path still hashed · version
line unchanged · duplicates keyed per folder · namespace trimmed or case-folded · root in / a folder missing from `folders` ·
unsorted lists · FAILED package with a non-empty tree · the package dir left in a 422 line · a referenced kind-less YAML
refused / an unreferenced one accepted.

## Done when
A package with two namespace folders validates, deploys and lists its tree; moving a flow file keeps its identity and swaps
nothing; a duplicate id in two folders is 422 naming both files; verify (incl. -Pit), ArchUnit, coverage no decrease; review PASS.

## Shape (designer, condensed)
- Module `flottila-sim` (root pom module + dependencyManagement; archtest test dependency). src/main `io.flottila.sim`: harness;
  src/test: variants, self-tests, pins. Deps api, core, testkit, junit. Rules.java: `SIM="io.flottila.sim.."`,
  `SIM_DEPENDS_ON_API_CORE_TESTKIT` (no sim class depends on runtime, components, steps, cli), `NOTHING_DEPENDS_ON_SIM`.
- The sim builds `new Runtime(FakeClock, SimTimer, SimIds, blobs, sha256, components)` itself; no src/main change in api, core,
  testkit, runtime (if one is needed: stop, write a finding).
- Scheduler: one driver virtual thread; units START (send on a new virtual thread), POLL (`worker.poll()` on the driver; a WorkQueue
  decorator caps a claim at 1 and answers `[]` to claims from any other thread — FlowWorker chain-end poll), RELEASE (SimPartner
  holds a call; signals, then parks in send()), WAKE (a Timer decorator treats a schedule from a run thread with Retry on its stack
  as a park and defers the task as a unit; FakeTimer fires all due tasks in one loop), ADVANCE (clock by nextDelay()). After each
  unit the driver waits until the runnable run is held, timer-parked or ended: run threads register by message id at their first sim
  call, end seen by join on a helper virtual thread, fast-path next items registered on the finishing thread; no sleep, no spin;
  per-seed @Timeout prints the unclassified run's stack. Every sim flow sets maxInFlight/bytes; no split, no RequestScope children;
  Targets above maxInFlight.
- Seeds: `record SimSeed(long run)`, `long of(Stream s)` = SplitMix64(run ^ s.salt); `enum Stream{WORKLOAD,FAULTS,SCHEDULE}` with
  explicit salts; per tick `SplittableRandom(mix(of(s), tick))`; per-call faults `mix(of(FAULTS), kind.code, messageId, attempt,
  callOrdinal) < rate`. Ids `<flow>-t<tick>-<k>`. `enum Action`, `enum FaultKind` explicit codes, append-only. `SimConfig.V1`
  (ticks, weights, rates, 4 keys, limits) frozen once pinned.
- Workload 10a with predictions: SEND_SYNC (Reply = partner(transform(body)); retryable Nack exactly when model in-flight = limit);
  SEND_ALO(key) (Accepted unless STORE_REFUSE hits ingress/enqueue → retryable Nack, nothing queued, or admission full); RESEND
  (Nacked payload r ticks later, new id); POLL by worker A or B on one InMemoryWorkQueue (≤1 item, oldest due of its key).
  Faults DELAY (partner holds 1..8 ticks), REFUSE (before effect: retries then DLQ row at the `to` step), STORE_REFUSE.
- Oracle `enum Check{PREDICTED,ADMISSION_BOUNDS,KEY_ORDER,ONE_ID_PER_DEDUPE_KEY,REPLAY_YIELDS_RECORDED,ACKED_IS_FINAL,
  SNAPSHOT_PER_STEP,DRAINED,EMPTY}` (10a uses all but ONE_ID and REPLAY). Per unit PREDICTED, ADMISSION_BOUNDS (permit holders ≤
  maxInFlight, bytes ≤ maxInFlightBytes, worker runs ≤ max; counted only at the limit), KEY_ORDER (≤1 id per (flow,key) at the
  partner; first receipts in seq order). After a bounded drain with faults off: ACKED_IS_FINAL, SNAPSHOT_PER_STEP, DRAINED.
  `Verdict(seed, config, failures, Map<Check,Long> compared, traceDigest)`; passed() needs no failure and Σcompared > 0 else EMPTY.
  Digest sha256 over events sorted by (tick, message id, seq), maps key-sorted.
- Variants (src/test, public seams only): ACK_BEFORE_SAVE (Intake decorator via FlowBuilder.intake answers at once, no save) →
  {PREDICTED, ACKED_IS_FINAL}; REORDERING_FAST_PATH (completeAndTakeNext hands out the newest due item of the key) → {KEY_ORDER};
  DOUBLE_ADMISSION (two deliveries for one flow, alternately) → {ADMISSION_BOUNDS}.
- Failure line `SIM FAIL seed=0x… config=V1 ticks=1000 world=correct check=KEY_ORDER tick=412: <detail>` + the replay command
  `mvn -B -ntp -q -pl flottila-sim -am test -Dtest=SimReplayTest -Dsurefire.failIfNoSpecifiedTests=false -Dsim.seed=0x…
  -Dsim.config=V1 -Dsim.ticks=1000 -Dsim.world=correct`. Pins: `flottila-sim/src/test/resources/io/flottila/sim/pinned-seeds.tsv`
  `seed⇥config⇥ticks⇥world⇥PASS|FAIL:Check,…⇥# origin`.
- Per push: correct world 32 seeds × 1 000 ticks; each variant runs those seeds until it fails. Floors per check = half the landing
  count, recorded in bench/RESULTS.md §P2-10 (machine, date, commit, JDK, V1, seeds×ticks, wall time median of 3, compared counts,
  detecting seed per variant).

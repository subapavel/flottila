# FIX-139 — newly created journal and key directories are durable in their parents (class A; review F7.5, F-29)

Architect 2026-11-09. Base: 0bafd2a.
Problem (confirmed in code, crash untested): Journal.java:378 and :395 and MasterKeySource.java:157 create directories with
Files.createDirectories and later force only the directory itself (Journal:396, JournalStart:212, MasterKeySource:174). The new
directory's entry in its parent is never forced, so on a first start a power loss after the first 202 can leave the journal path
unreachable (Linux fsync(2): an fsync of the file does not make its directory entry durable).

## Decision
One helper `JournalIo.createDirectoriesDurably(JournalFiles files, Path dir)`: find the nearest existing ancestor, create each
missing level in order, and force the parent of every level it created (then the level itself), through `files.open` so a test can
record the forces. Every journal and key directory creation uses it: Journal:378 (journal dir), :395 (segments), :446 (spill —
unless its contents are cleared at every start and nothing durable lives there; then say so in a comment and leave it), and
MasterKeySource:157. An existing directory is not forced again (no extra syscalls on a normal restart). Deploy/admin directories are
out of scope.

## Red tests (test-author)
JournalIoTest (or JournalDurableDirTest), with a recording JournalFiles over a temp dir:
.creatingANestedDirectoryForcesEachNewLevelsParent (a/b/c from an existing root: forces root, a, b, then c; in that order),
.anExistingDirectoryIsNotForced, .aFailedForceFailsTheCreation (the exception surfaces, never swallowed).
Journal / MasterKeySource level: a first start on a missing nested path forces every new parent (recorded), a second start forces no
parent above the journal dir. Red log agent/work/FIX-139-red.log.

## Checks
`mvn -B -ntp -q -pl flottila-runtime -am verify -Pit` with fresh-XML totals, coverage no decrease, scoped PIT on the helper, a hand
mutant dropping the parent force (killed), restore cp+touch+cmp with the diff in the mutant log.

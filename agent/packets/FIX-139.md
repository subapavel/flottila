# FIX-139 — a CI guard on ledger table shape

Class A. Depends on FIX-132 (done, a31a26d). Small, self-contained, `ci/` only.

## Why it exists

FIX-132 fixed eleven malformed rows across the two ledgers, ten of which were silently losing text
when GitHub rendered them. Nothing stops that from coming back, and during FIX-132 itself it came
back twice in one day: the architect dropped a row's closing pipe while editing it, then wrote two
raw pipes into FIX-132's own evidence cell while describing how to escape them.

**Counting pipes is not the check, and must not be the check.** FIX-54, FIX-56 and FIX-57 each had
the "right" count of 7 and seven cells, because a stray separator was paid for by a missing closing
pipe. A pipe-counting check called all three clean while GitHub dropped their entire evidence cell.
That is the case this guard exists to catch, and the done-when requires a red case shaped like it.

## The rule, decided here so the implementer does not have to guess

For each markdown table in `agent/BACKLOG.md` and `docs/DECISIONS.md` (`PROGRESS.md` has no tables —
the FIX-139 row listed it and was wrong), take the cell count from the header row, then for every
non-separator row of that table:

- it must END with an unescaped pipe. A row that does not is a defect even when GFM tolerates it,
  because 257 of 260 BACKLOG rows do and the three that did not were all broken in a second way.
- splitting it on pipes NOT preceded by a backslash must give exactly the header's cells in
  `agent/BACKLOG.md`.
- in `docs/DECISIONS.md` it must give AT MOST the header's cells. **Decision: the 32 legacy rows with
  no `Reason` cell are tolerated, not filled.** Filling 32 long design rows is content work with a
  real chance of putting words in a past decision's mouth; a missing trailing cell renders as an
  empty cell and loses nothing. Over-count is what loses text, and that is what the guard refuses.

A failure names the file, the line number, the expected cell count and the actual one, and exits
non-zero. One message per bad row, all bad rows reported in one run rather than only the first.

## Where it goes

Follow `ci/coverage_check.py` exactly — it is the precedent for everything here:

- `ci/ledger_check.py`, a module with a `main()` and the same argument style, runnable as
  `python3 ci/ledger_check.py` from the repository root.
- `ci/test_ledger_check.py`, tests in the style of `ci/test_coverage_check.py` (unittest, `tempfile`,
  fixture strings built in the test, no network, no repository files read by the tests themselves).
- wire BOTH into `.github/workflows/ci.yml`: the unittest run beside line 65
  (`python3 -m unittest ci.test_coverage_check`) and the check itself beside the coverage steps at
  lines 80-82. Keep the existing steps untouched.

## Red tests (test-author, before the script exists)

In `ci/test_ledger_check.py`. Three must be red and stay red if the guard is weakened:

1. a row with an extra unescaped pipe added → non-zero, and the message names that row's line number
2. a row with its closing pipe removed → non-zero, naming the line
3. **a FIX-54-shaped row**: a stray separator AND a missing closing pipe, so the pipe COUNT still
   matches the header while the cell count does not → non-zero. A guard that counts pipes passes this
   row, so this case is the one that pins the rule rather than an implementation of it.

Plus: an unmodified fixture of each shape exits 0, a DECISIONS fixture with a legacy `Reason`-less row
exits 0, and an escaped `\|` inside a cell does not count as a separator.

Write the fixtures as strings in the test. Do NOT make the tests read the real `agent/BACKLOG.md` —
a test that fails because someone edited a ledger is a test that will be disabled within a week.

## Done when

The three red cases above fail the check with their line numbers, the unmodified tree exits 0, and
`python3 -m unittest ci.test_ledger_check` passes. Run the guard against the real ledgers once by
hand and report the result: it should be clean at this commit, since FIX-132 left both files
well-formed.

## Allowed paths

- `ci/ledger_check.py` (new), `ci/test_ledger_check.py` (new), `.github/workflows/ci.yml`

Nothing in `agent/` or `docs/` is edited by this task. If the guard finds a real malformed row, do NOT
fix the row — report it, because that is a finding about a ledger and belongs to whoever owns that row.

## Note for the reviewer

This guard catches SHAPE, not content. Every ledger error that cost time today was a false SENTENCE,
not a broken table, and no CI check will catch those. Do not let this row imply otherwise.

## Red that means something (architect addendum, before dispatch)

A Python test suite against a module that does not exist reds with `ModuleNotFoundError`, and that
single error says nothing about whether any of the three cases can fail for its own reason. So the
test-author also writes `ci/ledger_check.py` as a **deliberately wrong stub**: the real argument
handling and a `main()` that prints nothing and returns 0 for every input. Every red case then fails
on its own assertion — "expected non-zero, got 0", with the fixture named — which is the red that is
worth observing. The hand-back must quote those three failures, not an import error.

The implementer replaces the stub's body and keeps its signature. The stub is the one piece of
non-test code the test-author writes here, and it is specified rather than invented.

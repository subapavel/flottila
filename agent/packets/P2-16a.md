# P2-16a — local hand-off: the saved item is written leased to its node, no claim (class C; D-102 (1), D-121 draft, F-30)

Architect 2026-11-10. Base: b554bb5. Design: designer draft (P2-16 split a/b/c), decisions below. P2-16b = events + reconciliation
(packet later), P2-16c = NOTIFY-in-commit cost at CORE-GATE (blocked: machine).

## Decision (draft — review at hand-over, D-121)
A1 core `final class Workers` (one per node, handed out by FlowBuilder like Targets): `Optional<FlowWorker.Slot> reserve(String flow)`,
   `void wake(String flow)`, `void wakeAll()`; a FlowWorker registers at start(), deregisters at stop(). `FlowWorker.Slot { Duration
   lease(); void run(WorkQueue.Item leased); void cancel(boolean mayHaveLanded); }`. reserve() is empty when the fence is closed, the
   worker stopped, room = max − running − reserved ≤ 0, or a backlog is known (a new arrival never overtakes a spilled row).
A2 `WorkQueue.enqueueLeased(id, flow, step, key, workerId, lease) → Future<Optional<Item>>` (default: plain enqueue, empty);
   InMemory and Pg implement it. PgWorkQueue ENQUEUE / ENQUEUE_REF / ENQUEUE_FROM gain `$node, $lease`: with a slot and the row heading
   its key (no other row of (flow, key); for ENQUEUE_FROM the source ref on $node) write locked_by=$node, locked_until=now()+lease,
   attempts=1, doubts=0; RETURNING seq, attempts, body_node beside the xid. Same statement, same group transaction (D-082 unchanged).
A3 Ordered keys (D-116): every keyed insert takes `pg_advisory_xact_lock(<class id>, hashtext(flow‖U+001F‖key))` for its group's keys,
   sorted, as the first statement of the rows turn (pipelined, after the dedupe turn). Keyed completes take the same lock pipelined
   with COMPLETE (closes F-30's lost hand-on). V15: index work(flow, partition_key, seq) where partition_key is not null.
   Accepted cost (O1): same-key intake groups serialise on the key's commit — a hot EOIO key gets at most one group per WAL flush.
A4 After the commit is acknowledged: leased → slot.run(item) (renew L/3, fence at sends/settles, park past maxAttempts as a claimed
   item); not leased (key busy) → cancel, the key's holder hands it on; no slot → workers.wake(flow) sets the backlog flag (no
   statement while full; the next chain end claims oldest-first); failed group → cancel(false); commit in doubt → cancel(true),
   one wake armed at now + lease.
A5 A reserved slot is never refused: it runs even after stop(); close() waits for reserved = 0; a closed fence runs it fenced. A node
   dying after the commit leaves the row as a claim would (lease, rejoin wait, CORE-5 takeover); a re-take counts a doubt.
A6 `pollingAfterAccept` removed (Deployments.java:1493 wires the delivery directly). A chain end claims only while the backlog flag
   is set (set by a spill, a wake, a claim that filled its room; cleared by a claim answering less than asked with no wake since it
   began). An item left to its lease (LEAVE, fenced settle, lost lease) arms one coalesced wake at its lease end. start() claims once.
   P2-16a keeps the 1 s tick (cross-node unchanged until P2-16b).
O2: interval and window are constants (no env key) until P2-16c. FlowWorker tests that expect a chain-end poll behind the worker
change by design: the test-author rewrites them and names each in the red log (wrong expectation, D-121).

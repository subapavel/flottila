## a [B] — node bench harness (after P1-09c)

- `NodeBenchMain` in flottila-bench: starts an in-process `Node` over native Postgres (dev env, dir archive store) with a bench
  package PUT through the admin API, and a local raw Vert.x HTTP echo as the partner. Options as BenchMain (`--messages`,
  `--warmup`, `--concurrency`, `--name`, `--out`, `--sync-commit`) plus `--scenario` and `--recording keep|metadata-only`.
- scenarios, each one JSON in bench/out (fields as BenchRun: p50/p90/p99/max ms, msg/s, machine label, config):
  - `sync`: HTTP → passthrough → HTTP partner → reply, against `raw` (the same client straight to the echo); the record carries
    both distributions and `overheadP50Ms = p50(sync) − p50(raw)`; keep and metadata-only.
  - `ack`: at-least-once ingress → 202 latency (durable save incl. the `bodies` insert, D-061), synchronous_commit on; c=8, c=64.
  - `worker`: queued items → msg/s and claim→complete p99; passthrough and a 100 KB XSLT; keep vs metadata-only.
  - each scenario also records `walBytesPerSecond` (pg_current_wal_lsn delta / duration), `bodiesBytesPerSecond`
    (pg_total_relation_size('bodies') delta / duration) and `bodiesGrowthPerHour` (extrapolated).
- `bench/run.sh` gains `BENCH_SCENARIOS` (default unchanged: the BatchingWriter pair only, so the CI regression job is untouched).
- tests first (flottila-bench): NodeBenchMainIT (Testcontainers Postgres) — eachScenarioWritesItsJsonWithTheNamedFields,
  syncRecordsTheRawBaselineAndTheOverhead, ackRunsWithSynchronousCommitOn, recordingMetadataOnlyWritesNoBodies,
  walAndBodiesRatesArePositiveAfterARun; NodeBenchMainTest — optionsAreParsedAndAnUnknownScenarioIsRefused.

## b [B] — kill -9 ledger (after a; GATE 9)

- `LedgerMain` (flottila-bench) + `LedgerIT`: node 1 runs as a child JVM (`ProcessBuilder`, same classpath) with an
  at-least-once bench flow over Postgres (+ LocalStack S3 in the IT, dir store natively); the driver sends N messages (2000
  natively, 200 in the IT), `destroyForcibly()` (SIGKILL) after N/2 ACKs, starts node 2 on an empty data dir (restore, P1-09c3b),
  sends the rest, waits with an `until` bound for work 0; then asserts and records sent (ACKed) = distinct final-step rows,
  DLQ 0, work 0, and no ACKed id missing. Duplicates (at-least-once) are counted and reported, not failures.
- tests first: LedgerIT — aKilledNodeLosesNoAckedMessage, theLedgerJsonNamesSentFinalDlqWorkAndDuplicates.

## c [B] — 50 MB through a stream step (after a)

- a stream-kind (`BodyKind.STREAM`) step in the bench package (passthrough that reads `open()` and writes a new body); a child
  JVM node at `-Xmx64m` takes a 50 MB HTTP body through it; heap after a forced GC sampled before and after (MemoryMXBean in the
  child, reported over its admin or stdout), growth < 8 MB and no OOM; the partner gets the same sha256.
- tests first: StreamHeapIT — fiftyMegabytesPassAStreamStepAtXmx64mWithoutHeapGrowth.

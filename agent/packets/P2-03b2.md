  flow's from endpoint (document mocks with the case's entry replacing it) — else a problem `<doc>: case '<name>' sends nothing: no
  send and no files/messages feed on '<from>'`; `expect.status` without `send` → problem `<doc>: case '<name>' expects a status but
  sends nothing`; a feed glob whose directory does not exist in the package → problem naming the glob.
- mock: `messages: <glob>` read as `files` by Behaviour (both given on one endpoint → refused at build with a message);
  `public Collection<String> undelivered(String endpoint)` = names remaining minus names finally refused (a final Nack or a final
  refusal is settled, not pending).
- runner: a feed case has no answer; settled = every from-endpoint feed has `undelivered` empty ∧ queue empty ∧ quiet; the
  fingerprint adds the from-mock's remaining count (a lock-free read: say how). `expect` keys that need an answer (`status`,
  `error` from the answer) → problems above; `error` on a feed case reads the first failed step's error from the timeline (or is a
  problem — choose and say). Report line unchanged (`PASS <flow>: <case> (flow time <d>)`).
- A cli fixture package with an sftp from endpoint (config valid against the real sftp schema: host key, user, password literal,
  maxBodyBytes) and fixture files; never edit packages/demo.

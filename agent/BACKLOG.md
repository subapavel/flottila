invents work outside this table without adding a row with a reason, and sets `done` only with a
`review: PASS` in `docs/PROGRESS.md`. Status: `pending | ready | in-progress | done | blocked`.
Evidence = commit hash + PROGRESS entry. Phase gates are rows; the next phase stays `pending`
until the gate row is `done`. Hand-over gate definition: `docs/GATE.md`.

Class (D-054, `AGENTS.md`): every row that is not `done` opens its title with `[A]` mechanical,
`[B]` standard, `[C]` hard path or `[G]` gate; the class sets the model and effort of each call.
A new row gets its class when it is written; the architect raises a class with a reason in the
row, never lowers it mid-task.

- CONSIDER-2: skip storing a step body whose bytes equal its input's. Today a step that does not change the body shares the same Body and key, so the trail persists it once (P1-09k2); but a step that builds a new body with identical bytes (e.g. an XSLT that changes nothing) gets a new key (id, step+1) and is stored again. Option: when a recorded body's hash() and size() equal the previous body's, the trail points the row at the previous key instead of persisting a copy — keys stay message id + step, never content hash. Cost: a hash compare per step; a byte compare on hash match to be exact; replay-from-step must accept a row whose key names an earlier step. Owner: deferred to the first real-world test phase (optimisations wait until measured on real load); not ready, no work before then.

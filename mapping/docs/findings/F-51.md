# F-51 — A constant fed into a context function is written into every Item

Status: accepted (owner observation `obs-lift-reuse` lift-4, PO 7.5 and CPI; the design judged by
the owner-proxy, subapavel/rail8#56). ADR-0004, ADR-0006, ADR-0025 and ADR-0026 amended in the same
ticket.

- **Assumption** (ADR-0004:65): a constant fed into a context or queue function is a queue of one
  context with one value, so it reaches the first Item only.
- **How it fails**: `obs-lift-reuse` lift-4: PO 7.5 and CPI both write `W = k` in all three Items (V = 1
  only in Item 1, from `count`). PO's display queue shows the constant as a gray start row and a dark-gray
  terminal row, with no extra ordinary value.
- **Severity**: major
- **Evidence**: `corpus/observations/obs-lift-reuse/{po75,cpi}/l4-lift-4.xml`, `po75/lift-4-queues.txt`,
  `l4.xml`; #212 comment "Owner decisions (2026-11-13, second set)", point 3; ticket #221.
- **Change made** (subapavel/rail8#56): the case `fn/removeContexts/004` (observed, the lift-4
  output: V = 1 in Item 1 only, W = k in all three Items). The catalogue gains the member
  `keepsSingleValue`, set on `removeContexts` alone, whose fidelity stays `exact`: lowering gives its
  call over single values only the atomic `FunCall`, a single value, which goes into every
  occurrence as a constant's does. The context family binds `removeContexts` among its single-value
  functions too, passing the value on; `po:removeContexts` takes and gives a queue or a single
  value. The pinned helper module re-pins `po:removeContexts` alone, and the pinned catalogue its
  entry alone (ADR-0026). ADR-0004 replaces its assumed reading at line 65; ADR-0006 records the
  graphs no observation shows yet as assumed readings (`removeContexts` over its own call, `concat`
  over it, `count` over it, `removeContexts` over `copyValue`), pinned by lowering tests and an
  agreement test on both back ends, and asked of the observation request subapavel/rail8#57.

# Rail8 Mapping — the engine's technical rules

The way of working is the repository's: `AGENTS.md` at the root. The rules below are the mapping
engine's own and hold inside `mapping/`.

Open-source mapping engine and editor: graphical message mappings (SAP PO style queues and
contexts) and, later, XSLT 3.0 / XPath 3.1, all compiled to one IR and run on Java 25. UI in
React + PatternFly.

## Read before work

- `docs/FOUNDING-ARCHITECTURE.md`: the agreed direction.
- `GLOSSARY.md`: the project's language. Use its terms in code and tests.
- `docs/adr/`: the decisions that bind the area you touch. Contradicting one needs the owner-proxy.
  Where an ADR prescribes a way of working (roles, tickets, integration branches), `AGENTS.md`
  overrides it.
- `docs/CODING_STANDARDS.md`: the coding standard.
- Checks, ratchet and CI: `docs/WORKFLOW.md` §6, the commands. Only the build with its tests
  blocks a change; coverage floors, mutation tests, the ratchet and Windows run nightly.

## Rules

- A change starts from a failing check: a test, an oracle case or a ratchet entry.
- Never weaken, skip or delete a test, an oracle case or a ratchet entry to go green.
- Ratchet files (`ratchet/`) are regenerated by their script, never edited by hand.
- Dependencies: Apache 2.0, MIT, MIT-0, BSD, EDL 1.0, ISC, 0BSD, MPL 2.0, EPL only; a dual licence
  counts under its allowed alternative. The list covers every compile, runtime and test dependency
  and all of the Rail8 UI's `../ui/package.json`. Exceptions are per artifact, listed in the
  mapping's POM: Saxon-HE at test scope (the oracle), JMH in `bench/jmh` only, the Quarkus test
  framework's own dependencies; and three dev-only npm build tools, listed in
  `../ui/scripts/licence-exceptions.json`. Maven plugins are tools (any OSI licence).
  A new dependency or licence exception is a question for the owner-proxy; a paid licence stays
  with the owner.
- No secret, customer payload or real partner data in the repository; corpora are synthetic.

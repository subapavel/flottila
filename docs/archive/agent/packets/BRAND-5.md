# Packet BRAND-5 (class B) — the namespace becomes `dev.rail8`

Row: `agent/BACKLOG.md` BRAND-5. Decision: D-154 (the owner, 2026-11-15: "rail8.dev, not io";
`issues/ISSUE-7.md`). Models: BRAND-1 commits B and C (`agent/packets/BRAND-1.md`), BRAND-3 step 2
(`agent/packets/BRAND-3.md`, D-151), the guard of BRAND-4 (`agent/packets/BRAND-4.md`).

`dev.rail8` replaces `io.rail8` everywhere it is a living name: the Maven groupId, the Java package
root, the mapping's JPMS module names, and every stored, wire or operator-visible name that carries
the namespace. No alias, no migration (D-148: nothing is released). History keeps what it said.
One commit. Measured on 2026-11-15: 1417 tracked files carry `io.rail8` (platform and bench 977,
mapping 414, elsewhere 26); 1334 files lie under 51 `io/rail8` directories.

## Part 1 — the red: the guard refuses the old namespace (test-author, then implementer)

`ci/name_guard.py` refuses the old product name today. It now also refuses the old namespace.

1. Test-author, `ci/test_name_guard.py` only: cases that fail today. The guard reports, exactly as
   it reports the old name (same finding lines, same exit codes, same allow-list semantics — a `*`
   entry, a covering literal, an unused entry is a finding): `io.rail8` and `io/rail8` in a line, in
   a tracked path, and in the bytes of a file that is not UTF-8; the regex-escaped spellings
   `io\.rail8` and `io\\.rail8`. It does not report a longer word that merely ends the same way
   (`studio.rail8`, `radio/rail8`: a letter, digit or `_` before `io` makes it another word), nor
   `dev.rail8`, nor `rail8.io`. The cases that exist stay untouched and green.
   Red observed: `python3 -m unittest ci.test_name_guard > agent/work/BRAND-5-guard-red.log 2>&1`.
2. Implementer: the guard, smallest change; its docstring says what it looks for. Then the guard run
   on the tree as it is, saved as `agent/work/BRAND-5-guard-before.txt` (last line: the count) — the
   failing check that defines this task.

## Part 2 — the rename (implementer)

A new subcommand `namespace` of `agent/tools/rail8_rename.py`, idempotent, with `--dry-run` and
`--root` like the others, built on the tool's own sets (`EXCLUDED`, `LIVING_DOCS`, `history_lines`):

1. `git mv` of every `io/rail8` package directory to `dev/rail8` (51 roots; `PACKAGE_DIR` of commit B
   is the model). A tracked path that holds `/io/rail8/` and is not under such a root is reported,
   never moved silently. `mapping/ui/dev/` exists and is unrelated.
2. In every tracked text file that is not history: each spelling the guard refuses becomes its
   `dev` form (`io.rail8` → `dev.rail8`, `io/rail8` → `dev/rail8`, the escaped spellings with their
   backslashes kept). The tool and the guard agree on what an occurrence is.
3. Import order. Under `platform/` and `bench/`: a contiguous block of `import` lines that was in
   ASCII order before the replacement is in ASCII order after it; a block that was not is left line
   for line; nothing outside import blocks moves. Under `mapping/` the engine's formatter decides:
   run its `spotless:apply` after the tool (its build checks the format).
4. What follows with the namespace, by the same replacement and not by hand: the JFR event names
   (`StepEvent.NAME`, `CpuSampler.DRAIN`), `Node`'s mock-package list, the ArchUnit package patterns
   (the pattern follows the renamed root; no rule changes its meaning), the mapping's groupId
   `dev.rail8.mapping`, its eleven `module-info.java`, the resource paths and `--add-opens` in its
   poms, the UI mock's UDF pattern, the class names in `bench/run.sh`, `bin/rail8` and the scripts.
5. Constants that depend on a renamed input. A known-answer constant or a pinned digest that turns
   red only because a name inside its input changed is recomputed outside the code under test,
   first reproducing today's value from today's input (`agent/work/BRAND-1-C-golden.py`; for the
   mapping D-151 and `agent/work/BRAND-3-s2-canon/`). A pin only the engine can produce is NOT
   regenerated: hand it back with its test, the architect decides. `mapping/contract/` is
   regenerated by the mapping's build and is part of the change.
6. `ci/name-allowlist.txt` changes only where an entry's path moved or where a history line inside
   a living file needs a literal (the changelog table of `docs/ARCHITECTURE.md` keeps `io.rail8`).

# Packet FIX-149 (class A) — a test port is never one the kernel may hand to somebody else

Row: `agent/BACKLOG.md` FIX-149, under MAIN-1 since `ci` run 220 failed on it (`agent/work/MAIN-1-ci.md`):

`NodeBenchOpenRecordingLevelIT.anAckOpenLoopWithRecordingLevelNoneSettlesAndSaysSo » IllegalState the node refused
the bench package: 500 {"error":"flow 'bench/bench' did not start: Address already in use"}` — the bench module's

(P2-15b, reactor run 1).

## The fault (read from the code)

Tests and the bench harness probe a "free port": bind port 0, read the number, close, hand the number on. The node
binds it later — in the bench after an echo server on port 0, `Node.start` (the admin server on port 0, the pools'
connections to Postgres) and the deploy (`NodeBenchMain` :420 → :432). Port 0 and every outbound connection draw
from one range, the kernel's `ip_local_port_range` (this container and the runners: 32768–60999), so anything
that binds 0 or connects between the probe and the node's bind can be given the probed number. Who took it on
the runner is not shown and cannot be; the remedy removes the whole class instead of one taker.

## The remedy (the architect's; hand back a better one before writing it)

One helper, `dev.rail8.testkit.Ports` (testkit main, JDK only, beside `PostgresImage` and `FakeClock`), hands out
ports from a pool **outside** the range the kernel chooses from, so that only an explicit bind to that number can
take one — and nothing in the tree binds an explicit number in the pool.

- `public static int free()` — the process-wide instance's next port. Unchecked on failure.
- Pool 20000–32767, minus the kernel's range. The range: on Linux the two numbers of
  `/proc/sys/net/ipv4/ip_local_port_range`; where that file does not exist, 49152–65535 (the IANA default of
  macOS and Windows). A file that exists and does not hold two port numbers is an `IllegalStateException` naming
  the file and its content — never a guess.
- A cursor walks the usable ports in ascending order and wraps. A candidate is handed out only if it could be
  bound on the wildcard address at that moment (`new ServerSocket(port)`, closed at once); one that cannot is
  skipped. One JVM never hands the same port out twice before the cursor has wrapped. `next()` is synchronized.
- After one whole pass with no bindable port: `IllegalStateException` naming the pool (a finite limit, said aloud).
- When the kernel's range leaves the pool no usable port at all (a host configured to choose from everywhere),
  the helper falls back to what the tree does today — bind 0 and hand that number on — and its Javadoc says the
  guarantee is gone on such a host.
- The process-wide instance starts its cursor at an offset derived from the process id, so that two JVMs on one
  host start apart. Not pinned by a test; say so.
- For the tests, package-private: a constructor taking the pool's bounds, the kernel's range and the start
  (`Ports(int poolFrom, int poolTo, int kernelFrom, int kernelTo, int start)`), `int next()`, and the range
  reader taking the file's `Path`.

Every probe in the tree goes through it; no call site changes:

- the eight `freePort()` definitions keep their signatures and return `Ports.free()`: `NodeIT` :587, `MainIT`
  :271, `MainProcessIT` :366, `QuickstartIT` :442, `NodeTakeoverLedgerIT` :481 (runtime), `DeployCommandIT` :143
  (cli), `HttpComponentTest` :207 (components/http), and `NodeBenchMain` :643 (bench **main**);
- the inline bind-0-and-close probes use `Ports.free()`: bench `NodeBenchMainHarnessTest` :86,
  `NodeBenchOpenEchoIT` :38; cli `DeployCommandTest` :71; runtime `S3ArchiveStoreTest` :32, `S3ArchiveStoreIT`
  :84, `NodeTest` :54, `PartnerFailureParkIT` :334, `PeerProtocolTest` :576, :590.

Untouched: sockets a test keeps open on purpose (`NodeIT` :406, :1245, :1282; `ValidateCommandTest` :115, :495;
`TestCommandTest` :803; `HttpComponentTest` :255) and every server that listens on port 0 and reads its port back.

## Acceptance

1. `PortsTest` (testkit, new) pins on instances built through the package-private constructor, with small pools:
   a port handed out lies in the pool and outside the kernel's range; it can be bound at once by the test; a
   held candidate is skipped (the test holds the next one and gets the one after); successive calls give
   distinct ports; the cursor wraps; a pool whose every usable port is held throws, naming the pool; a pool with
   no usable port falls back to a kernel-chosen port that can be bound; eight threads taking fifty ports each
   get four hundred distinct ports. The range reader: the two numbers of a file, the default for a missing
   file, the exception for a malformed one.
2. `Ports.free()` on this host: outside the range `/proc/sys/net/ipv4/ip_local_port_range` holds here (read in
   the test, when the file exists), inside 20000–32767, bindable.
3. Red: the type is new, so `PortsTest` not compiling is the red (the test-author's rule). In the same change
   the test-author moves the seven test definitions and the nine inline probes to `Ports.free()`.
4. Green: the implementer adds `Ports` and moves `NodeBenchMain.freePort()`. testkit's own tests green with the
   count stated; then the whole reactor (`clean verify -Pit`) by the verifier — every module at its count plus
   the new cases, 0 failures.
5. The row's "no flake in 20 runs" is replaced: twenty runs cannot show the absence of a fault seen twice in
   hundreds; the acceptance is the construction above, pinned by 1 and 2.
6. No sleep, no wall-clock wait. No new dependency.

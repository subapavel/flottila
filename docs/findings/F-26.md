# F-26 — the node's Postgres pool does not cache prepared statements

Date: 2026-11-04 · Task: CORE-6a · ARCHITECTURE section: §4 Writer

- **Assumption in the document:** §4 Writer: "fixed-shape `unnest` inserts with prepared-statement cache".
- **How it fails in practice:** Node.java:175 builds the pool's PgConnectOptions without `setCachePreparedStatements(true)`;
  every prepared statement costs two waits (Parse/Describe/Sync, then Bind/Execute/Sync), 8 waits for a level-none save
  (PgIntakeJournalIT:236-238). The intake pays it on every message (F-18's lost throughput).
- **Severity:** minor
- **Evidence:** PgIntakeJournalIT.levelNoneSavesRecordAndWorkItemOnly counts at the client (CORE-4c2); designer read of
  Node.java:175 (CORE-6 design, 2026-11-04).
- **Change made:** CORE-6a: one `Node.connectOptions(NodeConfig.Pg)` with the cache on, shared by the node and the counting ITs;
  the save's statements pipelined per turn (D-109). The document's intent stands; the code now follows it.

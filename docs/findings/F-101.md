# F-101 — the calibration's child-JVM test classes leave PIT's test set

- **Assumption** (ADR-0014 step 2, ADR-0020 "JUnit and PIT", F-84): every test class of a class-C
  module is in PIT's test set, and each exclusion needs a finding with its seconds and first-kill
  counts.
- **How it fails**:
  - #113's `CalibrationTest` and #111's `DeepStackFreshJvmTest` (moved onto `ChildJvm` by #113) do
    their work in fresh child JVMs. A child loads jq-core's and query-core's classes from the class
    path on disk, and PIT's mutants exist only in the minion's memory, so no child ever runs a
    mutant. Only the in-process part of a test can kill one.
  - Every minion start runs its test classes once before any mutant (F-84), and both classes start
    many children: `CalibrationTest` takes 27.1 s in surefire (its untagged column, proof, carrier
    and native tests; PIT's slowest test, `everyCellSwitchesBeforeTheBackstop`, 24.6 s), and
    `DeepStackFreshJvmTest` 9.2 s.
  - Kills, measured with only these two classes as PIT's tests on jq-core (3 543 mutants):
    `CalibrationTest` kills 0, as its untagged tests run no main code in-process.
    `DeepStackFreshJvmTest` kills 299, and 7 more time out, all through
    `reserveCoversTheGuardPages`, whose in-process `explain()` of `CallRuns.F` covers 3 078 blocks.
    These counts bound the classes' first kills in a full run. `StackUnitsTest` and `ExplainTest`
    run the same in-process `explain()`, so the spec gate's PIT run shows whether any of the 306
    survives without it; a survivor gets a fast test, or the gate stays red (F-84 (a)).
- **Severity**: minor. Leaving a class out can only lower the score, so no test is weakened.
- **Evidence**: #113 implementer, 2026-11-15, impl/113 after c732404 at b 192 and reserve 280 KiB:
  `.logs/113-k2-tests.log` (surefire times, JaCoCo off); `.logs/113-pit-child.log` and
  `.logs/113-pit-child-reports/mutations.xml` (`./mvnw -o -B -pl jq-core test-compile
  org.pitest:pitest-maven:mutationCoverage -DtargetTests=<the two classes>`, with the POM list
  replaced by an empty one; 282 s).
- **Change made** (ADR-0046 #113 "Rulings on the red", K10):
  - `CalibrationTest` and `DeepStackFreshJvmTest` go into jq-core's `excludedTestClasses`, each
    with its seconds and first-kill count, never as a `-D` property. Oracle's list does not take
    them: oracle's test class path has no jq-core test classes.
  - `CalibrationRecordTest` reads the record in-process and stays in PIT's set.
  - `scripts/test/pit-exclusions-test.sh` expects the two classes in jq-core's list.
  - Both classes still run in step 1 of both gates; the `calibration-matrix` tag runs only under
    its profile (the spec gate and nightly).
  - This is not a PIT-scope change (K10). `quality/floors.tsv` and `ratchet/` are not touched.

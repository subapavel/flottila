# F-7 — a parked message's body is node-local, so the DLQ does not survive a restart

Date: 2026-10-27 · Task: P1-09j · ARCHITECTURE section: §6 (version 3.4)

- **Assumption in the document:** CLAUDE.md and §6 (state rule): "state whose loss loses messages goes to Postgres (… DLQ …)"; a parked message can be retried later.
- **How it fails in practice:** `Parking.park` writes the DLQ row in Postgres, but the body it refers to (the body as of step k) lives in this node's memory or spool tier. After a restart, or on another node, a DLQ retry (P1-09c) fails with "no object stored under". The row survives; the message does not.
- **Severity:** major
- **Evidence:** P1-09h designer draft 2026-10-27 (TieredBlobStore index and spool key are per start, P1-09b; `Parking` never calls `persist`).
- **Change made (P1-09j, D-062):** `Parking.park` persists the parked body, then writes the row, in sequence; a failed persist fails the park and writes no row, the item reruns and past its bound parks the durable ingress. Earlier plan: New row P1-09j: park awaits `BlobStore.persist` of the parked body under the same bound as at-least-once ingress (D-058), before the DLQ row counts as written. A body above the bound is design work for P1-09j (S3 in P2-05 is the documented home).
- **ARCHITECTURE.md edit:** §6 "Retry per step", changelog 2026-10-27
- **PROGRESS entry:** P1-09j marked `Deviation: F-7` if the design changes a documented mechanism
- **For the owner's review:** not applicable — sync flows never park (D-045); the at-least-once body above the bound parks its ingress instead (D-062).

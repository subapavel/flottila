# F-19 — a deployed sftp endpoint cannot name its server or directory

Date: 2026-10-29 · Task: P2-06 · ARCHITECTURE section: §7 Component SPI (version 3.4)

- **Assumption in the document:** the sftp component's javadoc (SftpComponent.java:59) reads the endpoint as
  `sftp://host[:port]/dir`; §7 gives each component an `EndpointConfig` (name, uri, options).
- **How it fails in practice:** Deployments builds every endpoint URI as `<scheme>://<id>` (Deployments.java:1403-1406), and the
  sftp CONFIG_SCHEMA (additionalProperties false) has no host, port or dir key. A packaged sftp endpoint therefore connects to a
  host named like its endpoint id, on port 22, in directory "". The ITs never noticed: they build the URI directly.
- **Severity:** minor (the document is silent on how a packaged endpoint names its address; no mechanism changes).
- **Evidence:** the two lines above; P2-06 red test SftpComponentTest hostPortAndDirOptionsWinOverTheUri.
- **Change made:** sftp gains optional `host`, `port`, `dir` options that win over the URI part (D-086); without them the URI
  decides, as before. http already carries host/port/path in its options, so this matches the existing pattern.
- **ARCHITECTURE.md edit:** none (minor)
- **PROGRESS entry:** P2-06 marked `Deviation: F-19`
- **For the owner's review:** whether endpoint addresses should instead be a typed field of the endpoint document for every
  scheme (rejected for now: it changes the endpoint schema and every component; options keep it local to sftp).

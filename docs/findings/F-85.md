# F-85 — Three query-core mutants are equivalent under the execution protocol

- **Assumption**:
  - ratchet/mutation.tsv holds query-core at 100 %.
  - ADR-0039: "A Break marks its token and returns false. Every node passes a false on at once."
  - ADR-0043: a tail emitter runs into a holder, and IfOp or BindsOp then takes its result.
  - ADR-0041: "a call with no arguments … shares one empty array".
- **How it fails**:
  - The rerun of spec 2a's gate (6e245f0) and #193 leave three query-core mutants that no test can
    kill.
  - `BreakOp.java:19`, FALSE_RETURNS. `RunState.breakTo` always returns false, so the mutant gives the
    same mark and the same answer.
  - `Holder.java:18`, FALSE_RETURNS. Every owner of a holder (IfOp:38, BindsOp:55) drops the run's
    answer, and a tail emitter emits last.
  - `IntrinsicManyOp.java:31`, `>` to `>=`. This changes only whether a zero-width loop allocates an
    empty array.
  - With them, query-core's score is floor-rounded below 100 %.
  - ADR-0041's wording also lags the code since ADR-0044: the empty array is shared only with no
    arguments *and* no loop slots.
- **Severity**: blocking (spec 2a's `regen` stays red).
- **Evidence**:
  - `.logs/spec56-regen.log`
  - `.logs/spec56-survivors-query-core.tsv`
  - the #193 reviews
  - the designer's and the grilling-adviser's rulings of 2026-11-14
- **Change made** (ticket #194; proposed by the designer, approved by the grilling-adviser for the
  owner under the delegation of 2026-11-14):
  - `RunState.breakTo` becomes `void`, and a Break returns the constant false. Its return-value
    assertion moves to `BreakOpTest`.
  - A Holder answers its one result with a stop. IfOp and BindsOp use that answer, and the false ends
    there. ADR-0043 and ADR-0039 are amended. GLOSSARY gains **Holder**.
  - IntrinsicManyOp tests `width != 0`. ADR-0041's wording is fixed.
  - Rejected:
    - a PIT exclusion, because it hides the mutant;
    - always allocating, against ADR-0041;
    - identity or allocation tests, because they assert no behaviour.
- **Owner's Monday list**:
  - the exported `RunState.breakTo` becomes `void`;
  - the Holder's stop, which amends ADR-0043 and ADR-0039;
  - ADR-0041's wording;
  - spec 2a's gate failing more than once, ruled under the delegation.

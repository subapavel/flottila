# F-25 — a deterministic simulation needs a module §12 does not have

Date: 2026-11-03 · Task: P2-10 · ARCHITECTURE section: §11, §12 (version 3.4)

- **Assumption in the document:** §12 lists every module with a strictly downward dependency direction; test infrastructure lives
  in `flottila-testkit` (api only, F-1) and the flow-test runner in `flottila-cli`.
- **How it fails in practice:** P2-10 needs a harness that runs the real core (FlowBuilder, Delivery, FlowWorker, Replay,
  admission) against in-memory stores and SPI doubles, and from P2-10d against runtime's Postgres stores. Core's test tree cannot
  hold the Postgres variant (core → runtime is a reactor cycle) and would re-run the simulation for every PIT mutant and count it
  inside core's 90 % floor; testkit may not depend on core (F-1); cli sees every module.
- **Severity:** minor
- **Evidence:** designer draft for P2-10 (agent/packets/P2-10a.md), flottila-archtest Rules.java and ModuleBoundaryTest
  (`DoNotIncludeTests` — the harness must be in src/main to be checked).
- **Change made:** a new module `flottila-sim` at the top beside cli: api, core, testkit (runtime from P2-10d only, for
  `io.flottila.sim.pg..`, with a rule change then); nothing depends on it; never shipped; ArchUnit rules `SIM_DEPENDS_ON_API_CORE_TESTKIT` and `NOTHING_DEPENDS_ON_SIM`.
  Coverage floor 75 % line and branch, no PIT (D-101).
- **ARCHITECTURE.md edit:** §11 row "Deterministic simulation", §12 row `flottila-sim`, changelog line (3.4).
- **PROGRESS entry:** P2-10a marked `Deviation: F-25`
- **For the owner's review:** whether the simulation earns its own module; a package in core's test tree was rejected (PIT cost,
  floor inflation, no Postgres variant).

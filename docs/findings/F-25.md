# F-25 — message bodies leave Postgres for a node-local journal (owner's core rework)

Date: 2026-11-03 · Task: CORE-3 · ARCHITECTURE section: §3, §5, §7 (version 3.4)

- **Assumption in the document:** §5/§7: at-least-once bodies are made durable in Postgres `bodies` "until S3 (P2-05)", step
  bodies too (D-064); S3 holds "bodies above memory tier"; every node can read a durable body (D-058, D-061).
- **How it fails in practice:** the stop-gap became permanent; bytes in Postgres cost ~3.5 KB WAL per 132 B message, one
  transaction and fsync per message, and the owner rejects both bodies in Postgres and S3 as the hot-path body store
  (docs/CORE-REWORK.md O-4..O-6).
- **Severity:** major
- **Evidence:** bench/RESULTS.md §P2-07, §P2-08 (WAL B/msg, commits/msg); the owner's brief (D-103).
- **Change made:** a node-local body journal (D-105, agent/packets/CORE-3.md): segments with per-record AEAD, one group-fsync
  writer, references in Postgres, retention by reference; a body is readable through a live copy holder, not from every node.
- **ARCHITECTURE.md edit:** status note already points at the brief; §3/§5/§7 rewritten in CORE-12.
- **PROGRESS entry:** CORE-3 marked `Deviation: F-25`
- **For the owner's review:** the on-disk format v1 and the V12 tables are expensive to reverse; S3 and a uniform ref row per
  body were considered and rejected (packet "Rejected").

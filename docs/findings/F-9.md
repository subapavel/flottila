# F-9 — XSLT run-time document reads are neither confined nor part of the effective hash

Date: 2026-10-27 · Task: P1-09d2a (documented), fix row FIX-40 · ARCHITECTURE section: §9 (version 3.4)

- **Assumption in the document:** D-052 confines every file a step reads; D-060 c swaps a flow when any package file it references changes.
- **How it fails in practice:** an XSLT's run-time `doc()` / `unparsed-text()` on a relative URI goes to Saxon's own resolver (CompileConfinement.java:67 covers compile time only). It reads the build dir unconfined and is not reported to the `reads` sink, so a changed lookup file never swaps its flow and a path outside the package is readable.
